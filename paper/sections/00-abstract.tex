Flexible job shops with several workshops and one vehicle fleet per workshop
must decide, for every operation, when it starts, on which machine it runs,
and which vehicle moves it. The three decisions are coupled, and an
energy-aware objective charges idle machines even when they do not change the
makespan. We build a controller with four agents: a rule selector and three
shop actors. A dual Set
Transformer encodes the operation and machine candidates; its machine encoder
groups the features into three views, so the model compares the views of one
machine before it compares machines. We train the low-level agents with a
shared group-relative advantage and no value critic, and a top-level policy
picks a rule prior for each agent every few steps. One pass produces a
schedule, fast enough to use interactively. It returns a
lower objective than rule-based dispatch and than adapted DRL baselines.
Against the random-key genetic algorithm the answer depends on the size. The
search returns a 12\% lower objective at $6\times6$; at $10\times6$ the paired
test does not separate the two; at $10\times10$ one pass is 20\% lower. That
crossover, not dominance at every size, is the operating point of the method: a
schedule in one pass for a shop that reschedules often. The encoder and the
multi-actor update also help in our runs.
