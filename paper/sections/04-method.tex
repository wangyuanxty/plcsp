\section{Method}
\label{sec:method}

\subsection{Overview}

The controller makes three decisions at every low-level step: which operation
to schedule next, on which machine, and with which AGV. Each decision is
produced by its own policy head. A top-level policy selects one rule for each
head every $\Delta T$ low-level steps. The selected rules bias the low-level
heads; they do not replace them. We refer to the resulting controller as
H-ST-GRPO. Figure~\ref{fig:method} summarizes the architecture and the
training loop.

Let $s_t$ be the state at low-level step $t$. The joint policy factorizes over
the three heads,
\begin{equation}
\pi_\theta(a_t\mid s_t)=
\pi^{\mathrm{job}}_\theta(a^{\mathrm{job}}_t\mid s_t)\,
\pi^{\mathrm{mach}}_\theta(a^{\mathrm{mach}}_t\mid s_t)\,
\pi^{\mathrm{agv}}_\theta(a^{\mathrm{agv}}_t\mid s_t),
\label{eq:factor}
\end{equation}
where the AGV factor is omitted when the AGV module is disabled. Each factor
is a categorical distribution over a candidate set. The candidate set is
masked to the feasible actions: an operation is feasible when its predecessor
is complete, a machine is feasible when the operation can be processed on it,
and an AGV is feasible when it belongs to the required workshop.

The low-level heads are trained with group-relative policy optimization
(GRPO) and no value critic. The top-level policy is trained with proximal
policy optimization (PPO) on the weighted-cost change of each segment. The
two levels are trained online in the same episode loop.

\paragraph{Design rationale}
The joint action is a product of three candidate sets, and its size grows
with the number of jobs, machines, and vehicles. The factorized policy
\eqref{eq:factor} avoids enumerating the product: each head scores its own
candidate set and the log-probabilities are summed. A shared advantage is
used because the team objective is scalar; a per-head critic would need
per-head return targets, which the environment does not provide. The rule
prior restricts the effective support of each head early in training; the
bias is soft, so a head can override the rule once its own estimate is more
accurate. The per-head costs at the top level give each head a signal that
the shared return does not provide, because the shared return changes for
reasons that are not attributable to a single head.

\subsection{State and action}

The state contains the partial disjunctive graph, the machine routes, the AGV
states, and the current weights. For the operation head, each unscheduled
operation is a token. A token carries operation attributes, the processing
time and power on each eligible machine, the load of each machine, and the
workshop of each machine. The resulting token has 33 features in the
experiments.

For the machine head, each machine is a token. The token has three feature
groups: identity and load ($m_1$), processing time and power for the current
operation ($m_2$), and transport distance to and from the current operation
($m_3$). The groups have 6, 8, and 3 features; $m_1$ becomes 10 features when
the AGV module is enabled, and $m_3$ becomes 8 features when the full
transport context is enabled.

For the AGV head, each AGV in the relevant workshop is a token. The token
carries its home workshop, its current position, its free time, and the empty
and loaded travel times to the pickup and drop-off machines.

An action is a triple: an operation index, a machine index, and an AGV index.
The operation and machine are selected at every low-level step. The AGV is
selected only when a transport is needed, that is, when the previous
operation of the same job is complete on a different machine.

\subsection{Set Transformer encoders}

\paragraph{Attention block}
All encoders use the same block. For a token matrix $H\in\mathbb{R}^{n\times d}$,
multi-head self-attention is
\begin{equation}
\operatorname{Attn}(H)=\operatorname{softmax}\!\left(
\frac{(HW_Q)(HW_K)^{\top}}{\sqrt{d_k}}\right)(HW_V),
\end{equation}
followed by a residual connection, layer normalization, and a position-wise
feed-forward network. The block is permutation-equivariant: a permutation of
the input tokens permutes the output in the same way. A pooling head maps the
token set to a permutation-invariant vector when a single representation is
needed.

\paragraph{Job encoder}
The job encoder applies two self-attention blocks to the operation tokens.
The output embeddings are scored by a linear head, and the masked softmax
over the scores gives $\pi^{\mathrm{job}}$. The number of tokens changes with
the number of unscheduled operations; the encoder has no position embedding,
so the same weights apply to any number of operations.

\paragraph{Machine encoder}
The three feature groups of a machine are projected separately to the same
width and form three tokens. An intra-machine layer (one layer, two heads)
compares the three tokens of that machine. The output is
pooled into one token per machine. A second stack (three layers, four
heads) compares machines. The machine head scores the
eligible machines for the chosen operation.

Grouping the features before attention keeps the token count at $3M$ instead
of one token per feature. It also lets the model compare the three feature
views of one machine before it compares machines. The intra-machine layer is
ablated in Section~\ref{sec:ablations}: removing it costs 65.32 on
$6\times6$.

\paragraph{AGV encoder}
The AGV encoder applies one self-attention block to the AGV tokens. The AGV
head scores the AGVs of the source workshop. For a cross-workshop transport,
the same head scores the AGVs of the target workshop; the two scores use the
same weights.

All three encoders are permutation-invariant over their candidate sets, so
the same weights apply to different numbers of jobs, machines, and AGVs.

\subsection{Multi-actor GRPO}

A group contains $G$ episodes on the same instance batch. Episode $i$
produces a scalar return $R_i$, the negative objective \eqref{eq:objective}
under the weights of the group. The group advantage is
\begin{equation}
\hat{A}_i=\frac{R_i-\operatorname{mean}(R_{1:G})}
{\operatorname{std}(R_{1:G})+\epsilon}.
\label{eq:grpo}
\end{equation}
The same $\hat{A}_i$ is used by the job, machine, and AGV heads. Each head
maximizes the clipped objective
\begin{equation}
L_i=\min\left(\rho_i\hat{A}_i,\
\operatorname{clip}(\rho_i,1-\epsilon_c,1+\epsilon_c)\hat{A}_i\right),
\end{equation}
where
\begin{equation}
\rho_i=\frac{\pi_\theta(a_i\mid s_i)}
{\pi_{\theta_{\mathrm{old}}}(a_i\mid s_i)}
\end{equation}
is the ratio of the summed log-probabilities of the active heads. The update
maximizes $L_i$ over the group. At the low level, no value critic, no
reference model, and no KL penalty are used.

The weights $w$ in \eqref{eq:objective} are sampled once per group and stay
fixed inside the group, so all returns in \eqref{eq:grpo} are comparable. At
evaluation the weights are fixed to $(0.4,0.4,0.2)$.

Sharing one advantage across heads keeps the team objective. It does not
distinguish the contribution of each head; the next subsection adds a
per-head cost signal at the top level.

\subsection{Top-level rule selection}

Every $\Delta T$ low-level steps, the top-level policy observes an
18-dimensional state: ten summary statistics of the partial schedule, the
machine load imbalance, the work in process, the fraction of busy AGVs, the
mean AGV wait, the recent change of the weighted cost, and the three current
weights.

Its action is a triple of rules:
\begin{itemize}
\item job rule: earliest start, earliest finish, shortest processing time, or
most remaining operations (4);
\item machine rule: shortest processing time, lowest processing energy, or
shortest transport time (3);
\item AGV rule: earliest free, nearest (minimum empty travel), or no rule
(zero bias) (3).
\end{itemize}

The selected rule adds a bias $b$ to the logits of the corresponding
low-level head,
\begin{equation}
\ell'_{i}(a)=\ell_{i}(a)+\alpha\,b_{i}(a),
\end{equation}
where $\ell_i$ are the logits of head $i$ and $\alpha=0.5$. The low-level
heads keep the final decision, so the rule acts as a prior rather than a hard
constraint. The bias is zero for the ``no rule'' AGV action.

The top-level reward of segment $k$ is the negative change of the weighted
cost,
\begin{equation}
r_k=-\left(F_{k+1}-F_k\right),
\end{equation}
and the top-level policy is updated with PPO and generalized advantage
estimation. The top-level state includes the current weights, so the selector
can condition the rule on the objective. This shared reward gives every head
the same signal; the next subsection replaces it with a cost per head.

\subsection{Per-head cost signals}

The three rule heads share one segment reward. To give each head its own
signal, we define a local cost for each head:
\begin{align}
c^{\mathrm{job}}_k &= C_{\max}+E_{\mathrm{idle}},\\
c^{\mathrm{mach}}_k &= \Eproc+\Ttrans,\\
c^{\mathrm{agv}}_k &= \Ttrans+W_{\mathrm{agv}},
\end{align}
where $W_{\mathrm{agv}}$ is the accumulated AGV wait in the segment. The
reward of head $i$ is the negative change of its own cost. Each head has its
own normalization, its own value baseline, and its own advantage. The three
heads are updated with the PPO clip on their own advantages.

The local costs are not a decomposition of \eqref{eq:objective}: the terms
overlap, and the sum of the three does not equal $F$. They are signals that
attribute a cost change to the head whose action is most directly related to
it. Section~\ref{sec:experiments} reports the effect of the selector against
the same controller without it.

\subsection{Training}

Low-level actors and the top-level policy are trained online for 200
episodes. A group contains $G=8$ episodes; the instance batch is resampled
every 8 episodes. The learning rate is $10^{-3}$ with Adam and no decay. The
PPO clip is 0.2, the entropy bonus of the top level is 0.01, and the gradient
norm is clipped at 0.5. The top-level policy performs four epochs per
episode. Evaluation is greedy on 100 instances with fixed weights.


Algorithm~\ref{alg:train} summarizes one episode.

\begin{algorithm}[t]
\caption{One training episode}
\label{alg:train}
\begin{algorithmic}[1]
\State Sample the group weights $w$; reset the AGV fleet.
\State Observe the top-level state $z$; select the rule triple $u$.
\For{each low-level step $t=1,\dots,JO$}
    \State Apply the rule bias to the three heads.
    \State Mask infeasible operations, machines, and AGVs.
    \State Select the operation, the machine, and the AGV.
    \State Update the partial schedule and the AGV states.
    \If{$t \bmod \Delta T=0$ and the episode is not finished}
        \State Close the segment; observe $z$; select a new rule triple.
    \EndIf
\EndFor
\State Close the last segment; compute $R_i$; update the low-level heads.
\State Update the top-level policy from the segment rewards.
\end{algorithmic}
\end{algorithm}

\paragraph{Complexity}
One low-level step evaluates the job encoder on $n_j$ operation tokens, the
machine encoder on $3M$ machine-feature tokens plus the machine set, and the
AGV encoder on the vehicles of one workshop. With attention, the cost of a
step is $O(n_j^2 d + M^2 d + A^2 d)$ in time and
$O(n_j d + M d + A d)$ in memory, where $d$ is the embedding width. An
episode contains $JO$ steps. A low-level update processes $G$ episodes for
four epochs. The top level processes four to seven decisions per episode.
The controller therefore scales linearly in the number of episodes and
quadratically in the largest candidate set, not in the product of the three
candidate sets.
