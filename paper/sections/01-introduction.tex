\section{Introduction}
\label{sec:intro}

Consider a shop with two workshops and six machines, where a job is processed
on a machine in the first workshop and then on a machine in the second. The
second machine is free, but the job is not, because it waits for a vehicle.
The first workshop has an idle vehicle, and the second workshop has a busy one.
If the dispatcher sends the idle vehicle, the job arrives at the boundary and
waits for the second fleet; if it waits for a vehicle of the second workshop
instead, the first machine stays idle. The choice changes the makespan, the
idle energy of both workshops, and the loaded travel time. A rule that always
sends the nearest vehicle cannot see this trade-off, and a rule that always
waits cannot see the first machine. Figure~\ref{fig:motivated} shows the shop
and the two transport cases.

This example is the setting of the paper. In a flexible job shop each
operation is assigned to one machine from a set of eligible machines, and the
operations on each machine are then sequenced. When the shop uses automated
guided vehicles (AGVs), a third decision appears, namely which vehicle moves
the job between two machines. The three decisions are coupled, because a
machine that finishes early may wait for a vehicle and a vehicle that is busy
delays the next operation. In an energy-aware objective the coupling is
tighter, since idle machines contribute to the objective even when they do
not change the makespan. The objective in this paper combines makespan,
processing and idle energy, and loaded transport time.

The problem is hard for three reasons. Assignment, machine sequence,
and vehicle sequence interact, because a shorter loaded trip can require a
longer empty trip and a machine that starts earlier can leave a larger gap on
another machine. At a step the joint action count is the product of the
candidate sets, which grows with the number of jobs, machines, and vehicles.
Three objective terms with different scales make the weights a
trade-off that changes across planning scenarios.

Dispatching rules resolve the three decisions in one pass. They are fast and
predictable, but their performance depends on the rule combination, and a
fixed rule cannot adapt to the state of the shop. Metaheuristics search the
assignment space and often return better schedules, at the cost of thousands
of schedule evaluations per instance. Constraint programming and
mixed-integer models give a bound or a strong
incumbent~\cite{yao2026cp}, but their run time grows quickly with the number of
operations and vehicles. Deep reinforcement
learning (DRL) offers a fourth option, a policy that constructs one schedule
in a single pass and can be reused across instances. Recent work applies DRL
to flexible job shops with AGVs~\cite{li2025tsmc,li2025plcsp,shi2025nested,
wang2025hierarchical}. Most of these controllers make the operation and
machine decisions and leave the vehicle to a rule, or solve the two layers
in sequence.

Three difficulties remain for a DRL controller in this setting. First, the
candidate sets change size at every step, because the number of eligible
machines depends on the operation and the number of available vehicles depends
on the workshop. An encoder must map a variable-size set to a fixed-size
representation without imposing an order. Second, the three decisions share
one return. A single scalar critic gives every agent the same advantage, so an
agent whose action changed the objective receives the same signal as one
whose action did not. Third, a top-level rule selector makes only four to
thirteen decisions per episode. The sample is small, and a counterfactual
baseline must generalize to actions that were not taken.

This paper studies a controller that addresses the three difficulties with a
shared architecture. Three actor networks make the operation, machine, and AGV
decisions. The operation and machine agents use a dual Set Transformer, whose
machine encoder groups its features into three views and applies attention
within a machine before it applies attention across machines. We train the
agents with a shared group-relative advantage and no value critic, and a
top-level policy selects a rule prior for each agent every eight low-level
steps, so each agent receives its own cost as the credit signal. We refer to
the controller as H-ST-GRPO.

Each choice follows from one of these difficulties. A Set Transformer is
permutation-invariant over its input set, so the same weights apply to any
number of operations or machines. Machine-internal grouping keeps the
token count linear in the number of machines and lets the model compare the
three feature views of one machine before it compares machines.
Group-relative advantage removes the critic, which is the component with the
fewest targets in this setting. A rule prior gives the low-level agents a
coarse action space to explore, and the per-agent costs give the top level a
signal that a shared return does not provide.

We make four contributions.

\begin{enumerate}
\item \emph{A multi-agent controller for joint production and logistics
scheduling across workshops.} The operation, machine, and vehicle decisions
are produced by three actor networks in one step, so the transport decision is
coupled to the machine decision that creates it. For a cross-workshop job, a
single AGV agent selects the source vehicle and, after the transfer between
the stations, the target vehicle.

\item \emph{A dual Set Transformer encoder with machine-internal grouping.}
The machine encoder projects three feature groups separately, compares them
within a machine, and then compares machines. With no position
embedding, the encoder applies the same weights to any number of operations, machines,
and vehicles.

\item \emph{A group-relative update for three heterogeneous agents.} The three
shop actors are trained with one group-relative
advantage~\cite{shao2024grpo}: the team return of an episode is normalised
within the group, and no value critic, no
reference model, and no KL penalty are used at the low level. With the same
architecture and budget, this beats PPO by 72.98 at $6\times6$ under the
protocol of Wang et al., by 98.38 under the full protocol, and by 56.02 at
$10\times6$.

\item \emph{A hierarchical rule selector with per-agent cost signals.} A
top-level policy selects a rule prior for each agent every few steps. Each rule
head receives the change of its own local cost as the reward, so the selector
can attribute a cost change to the agent whose decision caused it. It lowers
the objective by 3.1\% at $6\times6$ (paired $p=0.0023$) and by 1.3\% at
$10\times6$, and the rule it selects shifts within an episode as the partial
schedule fills.
\end{enumerate}

We compare the controller with rule-based,
metaheuristic, and adapted DRL baselines on the same instances,
against the same objective and under the same transport model. We report the
objective and the run time of every method, the per-instance spread, and the
scope of the transport model. One schedule takes about 0.95~s per instance.
