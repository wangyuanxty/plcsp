\section{Introduction}
\label{sec:intro}

Consider a shop with two workshops and six machines. A job is processed on a
machine in the first workshop, then on a machine in the second. The second
machine is free, but the job is not: it waits for a vehicle. The first
workshop has an idle vehicle, and the second workshop has a busy one. If the
dispatcher sends the idle vehicle, the job arrives at the boundary and waits
for the second fleet. If it waits for a vehicle of the second workshop, the
first machine stays idle. The choice changes the makespan, the idle energy of
both workshops, and the loaded travel time. A rule that always sends the
nearest vehicle cannot see this trade-off; a rule that always waits cannot
see the first machine. Figure~\ref{fig:motivated} shows the shop and the three
transport cases.

This example is the setting of the paper. A flexible job shop assigns each
operation to one machine from a set of eligible machines and sequences the
operations on each machine. When the shop uses automated guided vehicles
(AGVs), a third decision appears: which vehicle moves the job between two
machines. The three decisions are coupled. A machine that finishes early may
wait for a vehicle, and a vehicle that is busy delays the next operation. In
an energy-aware objective the coupling is tighter, because idle machines and
empty vehicle travel contribute to the objective even when they do not change
the makespan. The objective in this paper combines makespan, processing and
idle energy, and loaded transport time.

The problem is hard for three reasons. The assignment, the machine sequence,
and the vehicle sequence interact: a shorter loaded trip can require a longer
empty trip, and a machine that starts earlier can leave a larger gap on
another machine. The number of joint actions at a step is the product of the
candidate sets, which grows with the number of jobs, machines, and vehicles.
The objective has three terms with different scales, and the weights set a
trade-off that changes across planning scenarios.

Dispatching rules resolve the three decisions in one pass. They are fast and
predictable, but their performance depends on the rule combination, and a
fixed rule cannot adapt to the state of the shop. Metaheuristics search the
assignment space and often return better schedules, at the cost of thousands
of schedule evaluations per instance. Constraint programming and
mixed-integer models give a bound or a strong incumbent, but their run time
grows quickly with the number of operations and vehicles. Deep reinforcement
learning (DRL) offers a fourth option: a policy that constructs one schedule
in a single pass and can be reused across instances. Recent work applies DRL
to flexible job shops with AGVs~\cite{li2025tsmc,li2025plcsp,shi2025nested,
wang2025hierarchical}. Most of these controllers make the operation and
machine decisions and leave the vehicle to a rule, or solve the two layers
in sequence.

Three difficulties remain for a DRL controller in this setting. First, the
candidate sets change size at every step: the number of eligible machines
depends on the operation, and the number of available vehicles depends on
the workshop. An encoder must map a variable-size set to a fixed-size
representation without imposing an order. Second, the three decisions share
one return. A single scalar critic gives every head the same advantage, so a
head whose action changed the objective receives the same signal as a head
whose action did not. Third, a top-level rule selector makes only four to
seven decisions per episode. The sample is small, and a counterfactual
baseline must generalize to actions that were not taken.

This paper studies a controller that addresses the three difficulties with a
shared architecture. Three policy heads make the operation, machine, and AGV
decisions. The operation and machine heads use a dual Set Transformer. The
machine encoder groups its features into three views, applies attention
within a machine, and then applies attention across machines. The heads are
trained with a shared group-relative advantage and no value critic. A
top-level policy selects a rule prior for each head every eight low-level
steps. Each head receives its own cost as the credit signal. We refer to the
controller as H-ST-GRPO.

The design follows from the difficulties. A Set Transformer is
permutation-invariant over its input set, so the same weights apply to any
number of operations or machines. The machine-internal grouping keeps the
token count linear in the number of machines and lets the model compare the
three feature views of one machine before it compares machines. The
group-relative advantage removes the critic, which is the component with the
fewest targets in this setting. The rule prior gives the low-level heads a
coarse action space to explore, and the per-head costs give the top level a
signal that a shared return does not provide.

The contributions are as follows.

\begin{enumerate}
\item \emph{A multi-agent controller for joint production and logistics
scheduling across workshops.} The operation, machine, and vehicle decisions
are made at the same low-level step by three policy heads, so the transport
decision is coupled to the machine decision that creates it. For a
cross-workshop job, a single AGV head selects the source vehicle and, after
the handover, the target vehicle.

\item \emph{A dual Set Transformer encoder with machine-internal grouping.}
The machine encoder projects three feature groups separately, compares them
within a machine, and then compares machines. The encoder has no position
embedding, so the same weights apply to any number of operations, machines,
and vehicles.

\item \emph{A multi-actor group-relative update without a value critic.} The
three heads share one group-relative advantage and are updated with the
clipped ratio of their summed log-probabilities. No value critic, no reference
model, and no KL penalty are used at the low level.

\item \emph{A hierarchical rule selector with per-head cost signals.} A
top-level policy selects a rule prior for each head every few steps. Each rule
head receives the change of its own local cost as the reward, so the selector
can attribute a cost change to the head whose decision caused it.
\end{enumerate}

Section~\ref{sec:experiments} reports the ablations that isolate each
contribution.

The controller is fast: one schedule takes about 0.56~s per instance. It is
not the best method in objective value. On the same 100 instances, a
random-key genetic algorithm obtains 478.04 and a two-stage mixed-integer
baseline obtains 505.05, against 556.70 for the controller.
Section~\ref{sec:experiments} reports this comparison, together with the
scope of the transport model.
