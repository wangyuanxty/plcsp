# 四条「交还决策权」机制的设计（2026-10-04）

> 依据：`progress-log.md` §28（发现"有约束、有观测、无动作"这一类）与 §30（机制总表）。
> 本文只为**开工前定死接口与验收判据**，不是 spec、不是计划。
> 每条开工时另写 brief。

## 共同点

四条都是同一模式：**某个决策现在由规则/机械过程包办，把它交还给策略。**

| | 约束 | 现在的决策者 | 交还给策略的决策 |
|---|---|---|---|
| **①** | 拥堵 | **没人**（`route_logits` 被砍，理由已失效） | 走哪条路 |
| **⑫** | 维护 | 规则（`pm_clock >= pm_interval` 自动触发） | 何时停机保养 |
| **⑪** | 充电 | 规则（比阈值 + 就近选桩） | 何时充、去哪个桩 |
| **⑩** | 拼批 | 规则（只看队首连续段） | 这趟带几件、带哪些 |

## 共同的实现骨架

四条都走**已有的候选打分模式**：

```
新增一个决策类型（链里一种 Decision.kind）
+ PolicyNet 新增一个 *_logits_emb(tok, feat_decision, feat_cand, cand_idx)
+ roll_chain 记录它、chain_logp 含它
+ 一个开关，关掉时**逐位不变**
```

**硬要求（四条一致）**：

1. **默认关 ⟹ 逐位不变**。既有读数全部建立在此。
2. **候选特征必须让选择非平凡**——要有测试证明"只改候选特征，分数会变"。
3. **一个能抓住"看不见"的守卫**：扰动**相关实体的特征** ⟹ 分数必须变。
   （L 头的教训：测试自己传下标，就抓不住生产路径的错。守卫必须走生产路径。）
4. **不新增 critic。** GRPO 保持 critic-free。

## T3 拉格朗日乘子：预算原则（2026-10-04 定）

### 机制

奖励加罚项，`λ` 自适应：

```
r' = r − Σᵢ λᵢ · activationᵢ
λᵢ ← max(0, λᵢ + η·(activationᵢ − bᵢ))        # 标准对偶上升
```

⚠️ **不需要 critic**——"PPO-Lagrangian" 是历史叫法，拉格朗日与值函数正交。**可做 GRPO-Lagrangian。**

### ⚠️ 定义的关键：激活量只算「**被迫发作**」

⑪⑫ 正在变成策略的**动作**（充电头、维护头）。
**若 T3 惩罚 `charge_events`（充电次数），就是惩罚策略使用它刚拿到的动作——自相矛盾。**

| 约束 | ❌ 不能算 | ✅ 该算 |
|---|---|---|
| **① 拥堵** | 走了绕路（**策略选的**） | **区段等待时长**（被迫等） |
| **② 有限缓冲** | — | **工件因缓冲满而等待**（被迫等） |
| **⑤ 换型** | — | 换型时长（可通过排序减少） |
| **⑪ 充电** | 充电次数（**策略选的**） | **电池耗尽导致停机**（被迫） |
| **⑫ 维护** | 主动保养次数（**策略选的**） | **被阈值强制触发**（被迫） |

**这条定义是整个 T3 的关键。不这样分，T3 会和 ⑪⑫ 头对打。**

### 预算 `bᵢ` 的锚：**照 ⑧ 交期那一套标定流程**

⚠️ **不锚在参考调度的绝对值**——**那正是 ⑧ 当年的错**：
参考调度太弱（`M_ref` 是可达水平的 2.4–4.06 倍）⟹ 任何像样的策略都轻松达标 ⟹ **目标恒 0、机制空转。**

正确流程（与 `TF_RDD` 同源）：

1. 在参考调度上测出该约束的激活量
2. 选**目标激活率**（如参考档的 50%）
3. 反推预算 `bᵢ`
4. **加"改进后不许退化"的约束**——策略改进 12% 后激活量**仍不得为 0**
5. **加"不许压死动作"的上界约束**（2026-10-05 补，用户裁定）——见下
6. **逐实例标定，冻结成表**（像 `TF_RDD`）

#### 第 5 条：预算标定必须**双侧**（下界防失效，上界防压死动作）

**预算 `bᵢ` 定得太紧 ⟹ T3 推着策略走极端**：因为"被迫发作"罚得重，而"策略主动做的动作"
只花时间。三种已知退化形态：

| 约束 | 预算过紧会把策略推成 | 退化形态 |
|---|---|---|
| **⑪ 充电** | **永远充电** | 与"模型修复前"**反向同一种退化**（那时是永远不充） |
| **⑫ 维护** | **永远保养** | 同上 |
| **① 拥堵** | **永远走最空的路**（哪怕绕远） | 绕路省下的等待 < 多走的距离，净亏 |

**上界判据**：**在基线策略上，该约束对应的动作分布不得退化成单一取值**——例如 ⑪ 的充电
动作使用率要落在中间带（既非 ~0 也非 ~1），可用**动作熵**或使用率上/下阈值钉；对 ⑫
（保养频率）与 ①（路径选择分布）同理。

**为什么这条紧要**：⑪ 的"耗尽模型修复"（§33）刚把 ⑪ 从"永远不充"救回来；**T3 若标定
过紧，会用另一种方式把它推回去。两者不能互相抵消。**

### 适用范围：**只有可控的 ①②⑤⑪⑫**

③④⑨ **无记忆、不可控**（§30.5 已验证）⟹ **不纳入**。
**罚它们等于罚策略无法控制的事，只会加噪。**

### 现有 metrics 的覆盖与缺口

| ② | ❌ **没有"因缓冲满而等待"的计数——要新增** |

## O3 目标权重自适应：准则（2026-10-04 定）

### 结论：**原样不成立，拆成两条**

#### O3 原样（无驱动的自适应）→ ❌ 划掉

**判据 1（有信号吗）不过**：**没有任何东西驱动权重更新。**

| 候选驱动 | 结果 |
|---|---|

#### ⚠️ 前置：**O1 必须先成为默认**

§29.1 实测：`scalar` 口径下**权重是装饰性的**
（方差份额 makespan 2.6% / energy 2.3% / **TWT 95.1%**，而名义权重 energy 88.6%）。

**在装饰性的权重上做自适应 = 自适应一个不起作用的东西。**

⟹ **O3 的任何形式都以"`adv_mode` 默认切到 `per_objective`"为前提**，

## R2 区段 token（① 拥堵的上下文相关排序）——动工前定死（2026-10-05）

> 依据：`method-transfer-candidates.md` §6.6（进基线、未做）与 §6.3（几何只作输入）；
> 现状见本文 §① 的"已知边界"：R 头候选之间的分差**只来自 `feat_cand`**——`tok` 与
> `feat_drive` 对所有候选是同一份输入。

### 决策点与动作（不变）

与 R 头**同点同动作**：每次行驶（`AgvSim._drive`）在 k 条候选路径里选一条（k = `route_k`）。
R2 **不加决策点、不改动作空间**，改的是 R 决策的**输入表征**：区段成为 token 进注意力，
且 R 头**逐候选**读该候选路径的区段 token。

### 开关

`route_zones: bool = False`（`roll_chain` / `joint_chain_step` / `ChainWorkerPool.run_chains`）。

- 默认关 ⟹ token 序列**逐位不变**（`seg` 仍是四元组、token 行数不变、R 头走原打分式）。
- 打开要求 `route_k > 1`，否则**显式报错**（没有 R 决策时区段 token 是死输入）。
- 与既有 `route_k=2` 读数不冲突：R2 关时 `route_k=2` 的链路逐位等于今日（本轮**改造前**
  捕获的摘要钉死，见验收判据 1）。

### 区段 token 怎么进四段序列（**设计决定，须写清**）

**末位追加第五段 "Z"**：`seg = (n_m, n_jobs, n_agv, 1, n_zones)`，**只在 R2 打开时**是五元组；
默认档仍是 `(n_m, n_jobs, n_agv, 1)`。理由：

1. 区段**不是** M/B/V/G 任何一种实体。塞进任何既有段（如把 G 段拉长、或把区段混进 V 段）
   会让该段的**分段投影权重**被迫用一组系数解释两种语义——这正是 2026-10-04 用分段投影
   取代单个共享 Linear 的理由（见 `encoder.py` 模块 docstring）。
2. **末位追加** ⟹ 既有四段的行号与列布局一位不变（`v_token_index` / `SEG_SLICE` 前四段照旧）。
3. `F_Z = 5 ≤ F_MAX = 11`，补齐规则与 token 张量宽度不变。
4. 新参数（`proj_z` / `zone_type_emb`）一律建在**既有参数之后**，且经 `torch.random.fork_rng`
   **不消耗全局抽签流**——否则既有层/头的随机初值会移位，默认关档的黄金摘要全部作废。

### 区段的状态量（只用已有的，不另造）

- `Snapshot.zone_holder`（逐区段当前持有者）——已在；
- `VehicleState.zone_wait`（逐车"此刻等了多久"）——已在。新增 `Snapshot.zone_wait`：把**同一个量**
  按区段聚合（每区段取"正在等它"的车中最大的等待时长；无人等 = 0.0）。原料是
  `ZoneManager.pending` / `pending_since`（放行/超时即清），**不新造状态**；
- `build_zone_map`（节点→区段映射）——已在。

**区段 token 特征（`F_Z = 4`）**：`[busy, wait_frac, zone_x, zone_y]`

| 列 | 含义 | 来源 |
|---|---|---|
| 0 | `busy` = 该区段此刻被某车持着（0/1） | `zone_holder[z] != -1` |
| 1 | `wait_frac` = 该区段上**最大**当前等待 ÷ `zone_wait_limit` | 上面那项聚合，与 V 段 `zone_wait` 同标度 |
| 2-3 | `zone_x` / `zone_y` = 区段成员节点坐标的均值 ÷ `bbox_diag` | `layout` 的 `node_xy`（含装卸站节点） |

后两列是**身份**：没有它，两个同占用状态的区段 token 完全同码，注意力无法区分"哪一段"。
聚合只取"最大等待"这一项（不另记排队车数）：`busy` 管占用、`wait_frac` 管压力，
再加一列计数与前者高度相关，收益小、面却大。

### R 头怎么读区段 token（候选不再是同一个 token）

逐候选：`tok_c[i] = tok[本车 V token] + mean(tok[候选 i 途经的区段 token])`。

- 候选之间的分差自此**不再只来自 `feat_cand`**：每条路径经过的区段不同 ⟹ 读到的嵌入不同；
- **均值池化**：对路径内区段置换不变、路径长度可变仍成立；不新增参数、不改头输入宽度；
- 区段按候选路径**去重且保序**（与 `_route_cand_feat` 同一去重口径）；
- 路径没有区段（退化）⟹ 退回本车 token，与今日同式。

### 验收判据

1. `route_k=1`（默认）与 `route_k=2, route_zones=False` 两条链**逐位不变**——两条各由一枚
   **改造前**捕获的链路摘要钉死（既有黄金摘要 + 本轮新捕获的 R2 关档摘要）。
2. `route_zones=True` ⟹ `seg` 是五元组、token 行数 = 四段和 + `n_zones`、R 决策记录逐候选
   区段 token 下标与掩码；同 seed 可复现。
3. **只改区段争用，R 头分数会变**（网络层）：两条候选的其余特征完全相同，只有途经区段的
   占用/等待不同 ⟹ 分数必须不同。
4. **守卫走生产路径**（§31 纪律）：对 `roll_chain` 记录的 R 决策，扰动其**途经区段**的 token ⟹
   `decisions_logp` 重算的 logp 必变；扰动**路径外**区段 ⟹ 不变。用逐 token 恒等嵌入的哑
   编码器切断注意力泄漏（同 M/C 头守卫），并**实地跑一遍错误实现**确认判据会失败。
5. 梯度：区段投影与 R 头都拿到非零梯度；R2 决策进链 logp。
6. 门禁 = `plcsp/tests/` 全绿 + `ruff check plcsp/` 干净。

### ⚠️ 边界（写明，不夸大）

- R2 **不加决策点、不改动力学**：打开后链与 makespan 变化只因策略输入变了（决策不同）。
- R2 只主张"让区段争用进入注意力、使 R 的候选排序上下文相关"；**跨布局/跨拓扑泛化不在
  主张内**（§6.3 的裁定）。
- 区段 token 的数量随 `zone_granularity` 变（默认 node 粒度：MK01 从 20 个 token 增到 33 个）
  ——这是打开档的墙钟代价，与默认档无关。

## 几何/度量偏置（② 拥堵的"距离可感知"）——动工前定死（2026-10-05）

> 依据：`method-transfer-candidates.md` §6.3 的裁定——**加回，但只作"输入"用途**：
> 让拥堵/距离可被感知。**不得**借它主张跨布局泛化（那是 2026-10-02 砍掉的卖点，§12.6）。
> 本仓 2026-10-02 删掉的 `GeomBias`（旧 `encoder.py`）是"加在注意力分数上的距离偏置"，
> 本项即按当年的形态恢复，但**限定用途**。

### 决策点与动作（不变）

**不加决策点、不改动作空间**：偏置只改编码器输入——所有头的上下文都变得更"距离敏感"。

### 开关

`geom_bias: bool = False`（`roll_chain` / `joint_chain_step` / `ChainWorkerPool.run_chains`）。
默认关 ⟹ 编码器走原表达式（`bias=None`），token/特征/链路**逐位不变**（既有黄金摘要继续守着）。

### 偏置的形态（**不新增可学参数**；沿用旧 `GeomBias` 的"固定系数"约定）

```
b(i, j) = −GEOM_BIAS_W · d(anchor_i, anchor_j) / bbox_diag        （两个锚都存在时）
        = 0                                                        （任一锚缺失）
```

- `d` = **通道图最短路距离**，取自 `dm`（`dock_distance_matrix(build_corridor_graph(layout))`
  ——与 `AgvSim._seg_min` 的行驶时长同一张矩阵、同一单位[米]）。**不另造距离量。**
- `bbox_diag` = `NormContext` 的包围盒对角线（既有归一化标度）。
- `GEOM_BIAS_W = 1.0`（模块常量，固定）：**负号** ⟹ 距离越近的实体注意力分数越高
  （距离衰减先验）；`1.0` 与注意力 `q·k/√d_h` 的 O(1) 量级同档。
- 偏置**对称**、对角为 0；缺锚的行/列全 0（中性，**不是哨兵**）。
- ⚠️ 非有限距离（图不可达）按缺锚处理（0），不传 NaN 进 softmax。

### 锚点（先查已有量，逐段）

| 段 | 锚 |
|---|---|
| M（机台 i） | `layout.machines[i].dock_node` |
| B（作业 j） | `at_machine >= 0` 且 < 机台数 ⟹ 该机台 dock；否则 `on_agv >= 0` 且该车 `node >= 0` ⟹ 该节点；否则**无锚** |
| V（车 a） | `vehicles[a].node`（`>= 0`；`-1` = 尚未出车 ⟹ 无锚） |
| Z（区段 z，R2 打开时才有） | 该区段的**最小成员节点**（从 `zof` 反查；row/col/all 粒度下一个区段含多节点，取最小号是确定性的） |
| G（全局） | 无锚（偏置行/列全 0） |

### 加在哪、怎么加

- `AttnLayer._attn`：`scores = scores + bias.unsqueeze(1)`（分头广播）——与旧 `DualAxisLayer`
  的写法同式，**在 softmax 之前**、**不在 `type_emb` 上**（偏置项与类型嵌入正交：
  类型嵌入改的是 token 的初始嵌入，偏置改的是注意力分数）。
- `LayoutEncoder.forward(tok_feat, seg, bias=None)`：`bias` 形状 `(N,N)` 或 `(B,N,N)`；
  `None`（默认）⟹ 一行代码都不走新分支，与今日逐位相同。
- **CUDA 图快路在 `bias` 非空时跳过**（图只捕获 `tok_feat` 一个输入）——如实记明。
- `Decision.geom_bias` 冻结采样时的偏置；`_decision_logp_terms` 堆成 `(B,N,N)` 一次性重算。

### 验收判据

1. **关档 ⟹ 逐位不变**：`bias=None` 时与今日同表达式；既有黄金摘要（`route_k=1`）继续绿；
   另设对照：同一个编码器喂**全零偏置**与**不喂偏置**，输出 `torch.equal`。
2. **打开 ⟹ 偏置真的进分数**：非零偏置改变注意力输出；`build_geom_bias` 的数值判据
   （对称、对角 0、缺锚 0、近的偏置 > 远的偏置、量级 ≤ `GEOM_BIAS_W`）。
3. **链级可观测**：`geom_bias=True` 的决策 logp 与关档不同（同一初始化、逐决策比）。
4. 梯度照常回传编码器；**批量重算与逐决策同源**（≤1e-5）。
5. 门禁 = `plcsp/tests/` 全绿 + `ruff check plcsp/` 干净。

### ⚠️ 边界（写明，不夸大）

- **只作输入**：本项只让距离/拥堵可被感知；**不得**借它主张跨布局/跨拓扑泛化（§6.3）。
- 固定系数（不可学）：不做系数扫描；若将来要学，须先立"它学出了什么"的判据。
- 偏置是**静态几何**（区段/实体的**当前**位置），不含"未来会不会堵"的预测。

## ⑨ AGV 故障：在途任务退回队列（failover）——动工前定死（2026-10-05）

> 依据：`method-transfer-candidates.md` §6.6（进基线、**改动力学**）与 `progress-log.md`
> §30.0 B 类：`AgvSim._failures` 只设 `down`/`up`，本车队列里的任务在停机期间**没人能碰**
> ——"车趴多久，任务就卡多久"。现实里任务会**退回队列、由别的车接**。
> ⚠️ 当前口径下 ⑨ 的代价只有停机时间；真实口径下是 **停机 + 重新派车 + 队列重排**
> ⟹ §3.3.2 对 ⑨ 的 binding 判定是在**低估口径**下做的。本项只报开关开/关的差，不重跑那张表。

### 决策点与动作（**不加决策点**）

退回是**规则**（故障期间退回/转交），不是策略动作。开关只改动力学：⑨ 从"停机只是少一台
运力"变成"停机还要重新派车 + 队列重排"。**"让策略选接管车"是另一个决策点（A 类），不在本项。**

### 开关

`SimConfig.agv_failover: bool = False`（仿真层参数——经 `cfg` 自动流到所有入口，不新增
`roll_chain` 形参）。默认关 ⟹ `AgvSim` 走原路径、逐位不变（既有全部读数）。

### 时点（不许改）

故障仍只在**腿间**生效：`_failures` 只设 `down`/`up`，**不打断正在进行的行驶**；
退回/转交只发生在**不持任何区段锁**的腿间点。**绝不在持锁时停机**——那会让同区段的车
永久等待（死锁），与 ⑪ 耗尽门的纪律同源。

**三个检查点**（都在 `_drive` 之外、车不持锁）：

| # | 位置 | 退回什么 |
|---|---|---|
| 1 | 循环顶（`_wait_up`，今日已有） | 停机期间**转交本车队列里**的任务 |
| 2 | `q.get()` 之后、空载段之前（**新**） | **本车刚取到、还没开始跑**的任务 |
| 3 | 空载段之后、装载段之前（**新**） | **本车刚装好的整批** |

检查点 2/3 是新增的：今日的故障只在循环顶被查，车在"等任务"期间趴窝后会**带着货跑完
整趟**（不真实）。时点仍是腿间、仍不持锁——**"故障不打断行驶"这一条没动**。

### 退到哪

- **`bound=True`**（每车一 Store，训练路径）：转交给**未停机的**其它车（从 `aid+1` 起
  轮转，确定性）。**不转给停机车**——那会在两辆停机车之间乒乓，计数虚增而任务原地打转。
  其它车全停机 ⟹ 检查点 1 不动（任务留在本车队列，等任一车恢复后再转交）；
  检查点 2/3 放回**本车队列**（车已不"手拿"，恢复后可跑）。
- **`bound=False`**（FIFO 单个共享 Store）：共享队列本来就人人可取，**无需动作**；
  只有检查点 2/3 手上已取走的任务要**放回共享队列队尾**（如实记明：这会改变 FIFO 相对顺序）。
- 轮询间隔 = `zone_hold`（确定性；停机是有界事件，轮询代价可忽略）。

### 记账

- `stats["agv_failover_tasks"]`：**实际被退回/转交的件数**（新键，两个 metrics 出口都带出）；
- `track.job_agv[job]` 指向**新的**持有者（bound）/ −1（放回共享队列）——否则快照的
  `in_transit` / `on_agv` 会滞留成假信号；
- 车上在运计数 `track.set_load(aid, 0)` 清 0；
- **任务不丢、不重复**：退回 = 从本车队列/hand 取出、放进**恰好一个**目标队列
  （SimPy 单线程；`Store.put` 在无界队列上同步生效）。

### ⚠️ 这是改动力学

打开后 makespan / travel / requeue 都会变——**预期**，是 ⑨ 的代价口径从"仅停机"改为
"停机 + 重新派车 + 队列重排"的**定义性后果**。docstring 写明。

### 验收判据

1. **关档 ⟹ 逐位不变**：默认档与故障高频档（`agv_mtbf=12, agv_mttr=5`）各两条摘要
   （`run_gated` 的 bound 路径 + `SimWorld.run` 的 FIFO 路径），**改造前**捕获、改造后复算
   逐字相同。
2. **打开 ⟹ 退回真的发生**：高频档下 `agv_failover_tasks > 0`，且 makespan 与关档不同。
3. **任务守恒**：完整跑完（`jobs_done == n_jobs`、无 `horizon_hit`）时
   `deliveries == tasks_put`（每件搬运恰好送达一次）。
4. **两种队列形状都正确**：`bound=True` 与 `bound=False` 都跑通、守恒、无掐表。
5. **不死锁**：高频档下无 `horizon_hit`（持锁停机若发生 ⟹ 同区段的车永久等待 ⟹ 掐表）。
6. 门禁全绿 + `ruff check plcsp/` 干净。

## ③ 机器故障率随役龄上升（Weibull 递增风险）——动工前定死（2026-10-05）

> 依据：`method-transfer-candidates.md` §6.6 / §6.7「③ 这一条的要害」：**役龄量本仓已有**
> （`pm_clock` = 主轴工时累计、**保养归零**）。改成 `fail_rate(age)` 后 **③ 从无记忆变有记忆**
> （`progress-log` §30.5 对 ③ 的结论失效），且 **⑫ 维护第一次有双重收益**。

### 决策点与动作（不加）

纯仿真层改动：故障率从常数变成役龄的函数。开关只改动力学。

### 开关与参数

- `SimConfig.machine_age_failure: bool = False`（默认关 ⟹ 逐位不变）；
- `SimConfig.machine_age_beta: float = 2.0`（**Weibull 形状参数，assumed**；敏感性扫 1.5/2/3）；
- 尺度 η = `SimConfig.pm_interval`（名义保养间隔 = `pm_clock` 的强制归零点）。

**前置（显式报错，不静默）**：开关打开要求 ③ `machine_failure` **与** ⑫ `maintenance` 都开——
- ③ 关：根本无故障可"随龄上升"（死开关）；
- ⑫ 关：`pm_clock` 根本不累加（设计如此）⟹ **役龄量不存在**，曲线没有自变量（死开关）。

### 曲线（标准形态，不自创）

Weibull 风险函数的**递增段**，按保养周期**均值匹配**：

```
λ(a) = base · β · (a / η)^(β−1)        （a = pm_clock ≥ 0，η = pm_interval > 0，β ≥ 1）
```

- `base` = `MachinePad.fail_rate`（既有的 assumed 常数率，量纲 1/min）；
- **β = 1 ⟹ λ ≡ base**：与今天的常数模型**同式**（内置退化自检点）；
- **β > 1 ⟹ λ 严格递增**（役龄越大越易故障）——可靠性工程里"耗损期"的标准形态；
- **[0, η] 上的均值 = base**：若机台按 η 周期保养，开关开/关的**平均**故障频次一致，
  差别只在"何时"——避免把"频次变了"混进"分布变了"；
- λ(0) = 0（β>1 的 Weibull 性质）：如实声明这是**纯耗损模型**，不含早期/随机失效。
  ⚠️ **可报告的后果**：役龄冲不到 η 的 episode（MK01 默认 ~25/120 主轴分钟）里，
  开档的实际故障频次**低于**常数档——这是模型的**主张**（年轻机台不磨损失效），不是 bug；
  基线冻结时若要把频次调回，应改 η/β，**不得**锚在参考调度上（⑧ 的教训）。

**引文（待核）**：Weibull, W. *A statistical distribution function of wide applicability.*
Journal of Applied Mechanics, 18(3):293–297, 1951.（**卷期页待核**——本机无原文；
β>1 = 耗损期是标准可靠性工程的常识，本批不引具体教材。）形状参数一律标 **assumed**，
敏感性 β ∈ {1.5, 2.0, 3.0}（实测见 `progress-log.md` §44）。

### 马尔可夫性（用户裁定，不许破）

自变量**只能是 `pm_clock`**（当前状态里已有）。**不许**引入"上次保养距今""距上次故障多久"
这类需要记历史的量——那会把 MDP 变成有记忆过程，是另一个量级的设计决定。

### ⑫ 维护头的**双重收益**（本项的定义性后果）

- 旧：⑫ 只有"避免强制停机落在坏时刻"一重收益；
- 新：保养把 `pm_clock` 归零 ⟹ 故障率回落到 λ(0) = 0——⑫ 多了一重"降低后续故障率"。
  ⚠️ 这给 M 头候选特征**已有**的 `pm_left` 维加了真实语义（它现在真的预测故障风险，
  不再只是一个"距强制停机还剩多少"的单调量）。

### 只对 ③（用户裁定）

④ 返工率随龄不是标准形态；⑨ 的电池循环虽可能但不如刀具磨损标准。**不推广到 ④⑨。**

### 验收判据

1. **关档 ⟹ 逐位不变**：默认档、短保养间隔档（`pm_interval=20`）、高故障率档
   （`fail_rate=0.05`，故障真的发生）三条摘要**改造前捕获、改造后逐字复现**。
2. **役龄越大故障越频**：`machine_fail_rate` 纯函数严格递增（β>1）；受控积分（伪 rng
   记录每次抽样的指数尺度 = 1/λ）：同一保养周期内尺度**单调下降**。
3. **保养后回落**：保养事件后 `pm_clock` 归零 ⟹ 下一次抽样的尺度跳回最大（λ(0)=0）。
4. **β=1 与关档同式**（退化自检）；β<1 显式报错（只有递增段在讨论范围内）。
5. 前置不满足（③ 关 / ⑫ 关）⟹ **显式报错**。
6. 门禁全绿 + `ruff check plcsp/` 干净。
