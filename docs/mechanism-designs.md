# 四条「交还决策权」机制的设计（2026-10-04）

> 依据：`progress-log.md` §28（发现"有约束、有观测、无动作"这一类）与 §30（机制总表）。
> 本文只为**开工前定死接口与验收判据**，不是 spec、不是计划。
> 每条开工时另写 brief。

## 共同点

四条都是同一模式：**某个决策现在由规则/机械过程包办，把它交还给策略。**

| | 约束 | 现在的决策者 | 交还给策略的决策 |
|---|---|---|---|
| **①** | 拥堵 | **没人**（`route_logits` 被砍，理由已失效） | 走哪条路 |
| **⑫** | 维护 | 规则（`pm_clock >= pm_interval` 自动触发） | 何时停机保养 |
| **⑪** | 充电 | 规则（比阈值 + 就近选桩） | 何时充、去哪个桩 |
| **⑩** | 拼批 | 规则（只看队首连续段） | 这趟带几件、带哪些 |

## 共同的实现骨架

四条都走**已有的候选打分模式**：

```
新增一个决策类型（链里一种 Decision.kind）
+ PolicyNet 新增一个 *_logits_emb(tok, feat_decision, feat_cand, cand_idx)
+ roll_chain 记录它、chain_logp 含它
+ 一个开关，关掉时**逐位不变**
```

**硬要求（四条一致）**：

1. **默认关 ⟹ 逐位不变**。既有读数全部建立在此。
2. **候选特征必须让选择非平凡**——要有测试证明"只改候选特征，分数会变"。
3. **一个能抓住"看不见"的守卫**：扰动**相关实体的特征** ⟹ 分数必须变。
   （L 头的教训：测试自己传下标，就抓不住生产路径的错。守卫必须走生产路径。）
4. **不新增 critic。** GRPO 保持 critic-free。

## ① 路线头 + R2 区段 token（**进行中**）

| | |
|---|---|
| 决策点 | 每次行驶（`AgvSim._drive`），空载段与载货段各一次 |
| 动作 | k 条候选路径里选一条（**k=2**） |
| 候选生成 | `corridors.k_shortest_paths(g, src, dst, k)`——按长度升序 |
| 候选特征 | 路径长度（对最短路归一）、途经区段数、**途经区段的当前争用** |
| 已实测代价 | 链长 120 → **235**（R=115），`joint_chain_step` 11.50 → **22.43 s**（**1.95×**） |

**已知边界**：R2（区段 token）**未做**。现在 R 头只能从逐候选特征打分，
`tok` 与 `feat_drive` 对所有候选相同——**候选之间的分数差只来自 `feat_cand`**。
上下文相关的排序需要 R2 token。**R2 待开。**

## ⑫ 维护头

| | |
|---|---|
| **现状** | `MachineSim`：`pm_clock += op.time`，`>= cfg.pm_interval`（默认 **120 min 主轴工时**）即自动停机保养 |
| **决策点** | 机台**空闲**时（要停机才能保养） |
| **动作** | 候选 = {**现在保养**, **不保养** }，二选一 |
| **决策特征** | 该机台的状态摘要 |
| **候选特征** | `pm_left`（距强制保养还剩多少主轴工时）、**当前积压量**（现在停机的代价）、episode 进度 |
| **权衡** | **现在停**：损失当下的加工能力<br>**推迟**：强制停机落在更差的时刻 |
| **前置** | ⚠️ **间隔要短到会触发**。MK01 现在**从不触发**（累积不到 120 min 主轴工时） |
| **前置的处置** | 按 §27.1 纪律一：**默认不动**，验证实例用**短间隔**档（`SimConfig(pm_interval=…)`） |
| **默认关** | 保持规则驱动 ⟹ 逐位不变 |
| **验收** | ① 关掉逐位不变；② 短间隔档下**保养决策真的发生**；③ 策略能把保养**提前**（即动作有效果） |

## ⑪ 充电头（**规格已确认**）

| | |
|---|---|
| **现状** | `_maybe_charge()`：`battery > battery_low×cap` 则返回，否则**按最近**选一个空闲桩 |
| **决策点** | AGV **空闲待命**时（与 `_maybe_charge` 同一处） |
| **动作** | 候选 = {**不去充**} ∪ {**各充电桩**} |
| **候选特征** | 到该桩的行驶时长、该桩的**排队/占用**、本车电量、本车剩余任务的预期耗电 |
| **权衡** | **早充**：花时间但现在<br>**晚充**：省时间但可能没电 |
| **⚠️ 前置（模型修复，用户已确认）** | 现在**电池耗尽没有任何后果** ⟹ 充电是**纯成本、零收益** ⟹ 最优策略是永远不充 ⟹ **决策退化** |
| **修法** | `battery <= 0` ⟹ 该车**不可用**，充到 `battery_high×cap` 才恢复。**判定放在"该车空闲、准备接新任务"时**——不半路趴窝、不在**持有区段锁**时停机（防死锁） |
| **验证实例** | **小电池档**——`m11_constraint_binding.py` **已有先例**（`battery_kwh=0.3`） |
| **默认关** | 保持规则驱动 ⟹ 逐位不变 |
| **验收** | ① 关掉逐位不变；② **停机真的会发生**（小电池档）；③ 策略能通过**早充**避免它 |

## ⑩ 拼批头

| | |
|---|---|
| **现状** | `AgvSim._collect`：从**队首连续段**取与首件**同 (取货点, 卸货点)** 的任务，最多 `capacity` 件 |
| **实测** | 平均每趟 **1.000 / 1.017 / 1.000** 件（mk01/mk07/mk10）——**拼批几乎从不发生** |
| **根因** | 那条规则为**保 FIFO 顺序**而只看队首连续段；拼批需要两个完全同向的任务**挨着** |
| **决策点** | AGV 取货时 |
| **动作** | 候选 = **预构造的若干批次**（不是逐个任务） |
| **候选生成** | **放宽到全队列**（不再只看队首连续段），枚举同向组，每组按容量截断 |
| **候选特征** | 该批件数、**插入这批会打乱多少个任务的相对顺序**、这批的总运输距离节省 |
| **权衡** | **拼**：省运输<br>**不拼**：保 FIFO 顺序 |
| **默认关** | 保持现有 `_collect` 规则 ⟹ 逐位不变 |
| **验收** | ① 关掉逐位不变；② **放宽后真的出现 >1 件的批次**；③ 策略的选择**改变运输时间** |

⚠️ **动作空间比前三条大**：候选是**批**，不是单个实体。
选"预构造的批次"而不是"逐个任务累加"，是为了**匹配已有的候选打分模式**、且**限制链长**。
（逐个累加会产生变长的二值决策序列，链长会明显膨胀。）
