# 四条「交还决策权」机制的设计（2026-10-04）

> 依据：`progress-log.md` §28（发现"有约束、有观测、无动作"这一类）与 §30（机制总表）。
> 本文只为**开工前定死接口与验收判据**，不是 spec、不是计划。
> 每条开工时另写 brief。

## 共同点

四条都是同一模式：**某个决策现在由规则/机械过程包办，把它交还给策略。**

| | 约束 | 现在的决策者 | 交还给策略的决策 |
|---|---|---|---|
| **①** | 拥堵 | **没人**（`route_logits` 被砍，理由已失效） | 走哪条路 |
| **⑫** | 维护 | 规则（`pm_clock >= pm_interval` 自动触发） | 何时停机保养 |
| **⑪** | 充电 | 规则（比阈值 + 就近选桩） | 何时充、去哪个桩 |
| **⑩** | 拼批 | 规则（只看队首连续段） | 这趟带几件、带哪些 |

## 共同的实现骨架

四条都走**已有的候选打分模式**：

```
新增一个决策类型（链里一种 Decision.kind）
+ PolicyNet 新增一个 *_logits_emb(tok, feat_decision, feat_cand, cand_idx)
+ roll_chain 记录它、chain_logp 含它
+ 一个开关，关掉时**逐位不变**
```

**硬要求（四条一致）**：

1. **默认关 ⟹ 逐位不变**。既有读数全部建立在此。
2. **候选特征必须让选择非平凡**——要有测试证明"只改候选特征，分数会变"。
3. **一个能抓住"看不见"的守卫**：扰动**相关实体的特征** ⟹ 分数必须变。
   （L 头的教训：测试自己传下标，就抓不住生产路径的错。守卫必须走生产路径。）
4. **不新增 critic。** GRPO 保持 critic-free。

## ⑫ 维护头

| | |
|---|---|
| **现状** | `MachineSim`：`pm_clock += op.time`，`>= cfg.pm_interval`（默认 **120 min 主轴工时**）即自动停机保养 |
| **决策点** | 机台**空闲**时（要停机才能保养） |
| **动作** | 候选 = {**现在保养**, **不保养** }，二选一 |
| **决策特征** | 该机台的状态摘要 |
| **候选特征** | `pm_left`（距强制保养还剩多少主轴工时）、**当前积压量**（现在停机的代价）、episode 进度 |
| **权衡** | **现在停**：损失当下的加工能力<br>**推迟**：强制停机落在更差的时刻 |
| **前置** | ⚠️ **间隔要短到会触发**。MK01 现在**从不触发**（累积不到 120 min 主轴工时） |
| **前置的处置** | 按 §27.1 纪律一：**默认不动**，验证实例用**短间隔**档（`SimConfig(pm_interval=…)`） |
| **默认关** | 保持规则驱动 ⟹ 逐位不变 |
| **验收** | ① 关掉逐位不变；② 短间隔档下**保养决策真的发生**；③ 策略能把保养**提前**（即动作有效果） |

## ⑪ 充电头（**规格已确认**）

| | |
|---|---|
| **现状** | `_maybe_charge()`：`battery > battery_low×cap` 则返回，否则**按最近**选一个空闲桩 |
| **决策点** | AGV **空闲待命**时（与 `_maybe_charge` 同一处） |
| **动作** | 候选 = {**不去充**} ∪ {**各充电桩**} |
| **候选特征** | 到该桩的行驶时长、该桩的**排队/占用**、本车电量、本车剩余任务的预期耗电 |
| **权衡** | **早充**：花时间但现在<br>**晚充**：省时间但可能没电 |
| **⚠️ 前置（模型修复，用户已确认）** | 现在**电池耗尽没有任何后果** ⟹ 充电是**纯成本、零收益** ⟹ 最优策略是永远不充 ⟹ **决策退化** |
| **修法** | `battery <= 0` ⟹ 该车**不可用**，充到 `battery_high×cap` 才恢复。**判定放在"该车空闲、准备接新任务"时**——不半路趴窝、不在**持有区段锁**时停机（防死锁） |
| **验证实例** | **小电池档**——`m11_constraint_binding.py` **已有先例**（`battery_kwh=0.3`） |
| **默认关** | 保持规则驱动 ⟹ 逐位不变 |
| **验收** | ① 关掉逐位不变；② **停机真的会发生**（小电池档）；③ 策略能通过**早充**避免它 |

## ⑩ 拼批头

| | |
|---|---|
| **现状** | `AgvSim._collect`：从**队首连续段**取与首件**同 (取货点, 卸货点)** 的任务，最多 `capacity` 件 |
| **实测** | 平均每趟 **1.000 / 1.017 / 1.000** 件（mk01/mk07/mk10）——**拼批几乎从不发生** |
| **根因** | 那条规则为**保 FIFO 顺序**而只看队首连续段；拼批需要两个完全同向的任务**挨着** |
| **决策点** | AGV 取货时 |
| **动作** | 候选 = **预构造的若干批次**（不是逐个任务） |
| **候选生成** | **放宽到全队列**（不再只看队首连续段），枚举同向组，每组按容量截断 |
| **候选特征** | 该批件数、**插入这批会打乱多少个任务的相对顺序**、这批的总运输距离节省 |
| **权衡** | **拼**：省运输<br>**不拼**：保 FIFO 顺序 |
| **默认关** | 保持现有 `_collect` 规则 ⟹ 逐位不变 |
| **验收** | ① 关掉逐位不变；② **放宽后真的出现 >1 件的批次**；③ 策略的选择**改变运输时间** |

⚠️ **动作空间比前三条大**：候选是**批**，不是单个实体。
选"预构造的批次"而不是"逐个任务累加"，是为了**匹配已有的候选打分模式**、且**限制链长**。
（逐个累加会产生变长的二值决策序列，链长会明显膨胀。）

## T3 拉格朗日乘子：预算原则（2026-10-04 定）

### 机制

奖励加罚项，`λ` 自适应：

```
r' = r − Σᵢ λᵢ · activationᵢ
λᵢ ← max(0, λᵢ + η·(activationᵢ − bᵢ))        # 标准对偶上升
```

⚠️ **不需要 critic**——"PPO-Lagrangian" 是历史叫法，拉格朗日与值函数正交。**可做 GRPO-Lagrangian。**

### ⚠️ 定义的关键：激活量只算「**被迫发作**」

⑪⑫ 正在变成策略的**动作**（充电头、维护头）。
**若 T3 惩罚 `charge_events`（充电次数），就是惩罚策略使用它刚拿到的动作——自相矛盾。**

| 约束 | ❌ 不能算 | ✅ 该算 |
|---|---|---|
| **① 拥堵** | 走了绕路（**策略选的**） | **区段等待时长**（被迫等） |
| **② 有限缓冲** | — | **工件因缓冲满而等待**（被迫等） |
| **⑤ 换型** | — | 换型时长（可通过排序减少） |
| **⑪ 充电** | 充电次数（**策略选的**） | **电池耗尽导致停机**（被迫） |
| **⑫ 维护** | 主动保养次数（**策略选的**） | **被阈值强制触发**（被迫） |

**这条定义是整个 T3 的关键。不这样分，T3 会和 ⑪⑫ 头对打。**

### 预算 `bᵢ` 的锚：**照 ⑧ 交期那一套标定流程**

⚠️ **不锚在参考调度的绝对值**——**那正是 ⑧ 当年的错**：
参考调度太弱（`M_ref` 是可达水平的 2.4–4.06 倍）⟹ 任何像样的策略都轻松达标 ⟹ **目标恒 0、机制空转。**

正确流程（与 `TF_RDD` 同源）：

1. 在参考调度上测出该约束的激活量
2. 选**目标激活率**（如参考档的 50%）
3. 反推预算 `bᵢ`
4. **加"改进后不许退化"的约束**——策略改进 12% 后激活量**仍不得为 0**
5. **逐实例标定，冻结成表**（像 `TF_RDD`）

### 适用范围：**只有可控的 ①②⑤⑪⑫**

③④⑨ **无记忆、不可控**（§30.5 已验证）⟹ **不纳入**。
**罚它们等于罚策略无法控制的事，只会加噪。**

### 现有 metrics 的覆盖与缺口

| 约束 | 状态 |
|---|---|
| ① | ✅ `zone_wait["total"]` |
| ⑤ | ✅ `setup_minutes_total` |
| ⑫ | ✅ `pm_events` |
| ⑪ | ◐ `battery_min_kwh` 是代理；**耗尽停机计数要等 ⑪ 的模型修复** |
| ② | ❌ **没有"因缓冲满而等待"的计数——要新增** |

### ⚠️ 前置

- **② 的激活指标要新增**（仿真层）。
- **⑪ 要先修模型**（电池耗尽现在无后果），否则 ⑪ 的激活量恒 0。
- **预算表要标定**——照 ⑧ 的标定脚本做法，产出一张冻结表。

## O3 目标权重自适应：准则（2026-10-04 定）

### 结论：**原样不成立，拆成两条**

#### O3 原样（无驱动的自适应）→ ❌ 划掉

**判据 1（有信号吗）不过**：**没有任何东西驱动权重更新。**

把候选驱动逐个试过：

| 候选驱动 | 结果 |
|---|---|
| 约束激活量 | **就是 T3**，重复 |
| 训练进度（早期探索 / 后期收敛） | **就是 T5**，重复 |
| "平衡各目标的改进幅度" | **任意**——凭什么要求等幅？ |

**三个候选里两个与别的机制重叠，第三个没有依据。**

#### ⚠️ 前置：**O1 必须先成为默认**

§29.1 实测：`scalar` 口径下**权重是装饰性的**
（方差份额 makespan 2.6% / energy 2.3% / **TWT 95.1%**，而名义权重 energy 88.6%）。

**在装饰性的权重上做自适应 = 自适应一个不起作用的东西。**

⟹ **O3 的任何形式都以"`adv_mode` 默认切到 `per_objective`"为前提**，
而那又需要 §29.3 的加长实验（30 步 × 3 种子分不开）。

### O3a：梯度冲突重加权（✅ 可做）

**驱动不是任意的**：**各目标策略梯度之间的余弦相似度**。

- 两目标梯度方向冲突（负余弦）⟹ 投影掉冲突分量（PCGrad / MGDA 式）
- **信号现成**：O1 已给出**逐目标的优势** `zᵢ(−fᵢ)`
  ⟹ 逐目标的代理目标与梯度**算得出来**

| 判据 | |
|---|---|
| 1 有信号 | ✅ 梯度余弦 |
| 2 非平凡 | ✅ |
| 3 改最优解 | ✅ |
| 4 不冗余 | ✅ |

⚠️ **新意低**——PCGrad / MGDA 是已知技术。**但它是"针对三目标"的，且驱动非任意。**

### O3b：权重扫描 → Pareto 前沿（✅ **必须做**）

**这不是机制，是实验设计。** 但它才是"三目标"的正确交代。

- 扫 M 个权重向量 × 若干种子 ⟹ 画前沿
- **成本可控**：MK01 上 30 步约 3 分钟；**5 点 × 3 种子 ≈ 45 分钟/实例**
- ⚠️ **没有它，"三目标"只是一句口号**——只有一个点，谈不上多目标

### 与别的机制的关系

- **O3a 与 T3 不重叠**：T3 调的是**约束罚项 λ**，O3a 调的是**目标之间的权衡**。
- **O3a 与 T5 不重叠**：T5 改的是**约束配置的日程**。
- **O3b 与两者都无关**——它是实验设计，不是训练机制。
