## 0. 一句话

**奖励加罚项，λ 对偶上升；无 critic。**

```
r' = r − Σᵢ λᵢ · âᵢ
λᵢ ← max(0, λᵢ + η · (âᵢ − bᵢ))          # 标准对偶上升
```

`âᵢ` = 第 i 条约束**归一化后**的激活量；`bᵢ` = 它的**预算**（目标水平）。

⚠️ **不需要 critic**——"PPO-Lagrangian" 是**历史叫法**，拉格朗日与值函数**正交**。
可做 **GRPO-Lagrangian**（本仓是 GRPO，不为此引入 critic）。

## 3. 罚项与 λ 更新

### 3.1 归一化：`âᵢ = aᵢ / aᵢ^ref`

**为什么必须归一化**：各约束的激活量量纲不同（分钟 / 次数），**λ 的尺度无从可比**。
除以**参考调度上同一口径的激活量** ⟹ `âᵢ` 是"**占参考水平的比例**"，`bᵢ` 可以取 [0,1] 的比例。

**⟹ `aᵢ^ref` 要进冻结表**（照 `TF_RDD` 的做法：逐实例、逐约束，标定一次、冻结）。

### 3.2 罚项加在哪

`r` 是**链的终端奖励**（`reward.scalar_reward` 的输出）。**罚项加在它上面**，**在组内 z 化之前**：

```
r_g' = r_g − Σᵢ λᵢ · âᵢ,g          # 逐链（G 条链各有自己的 â）
A = z(r')                          # 之后照旧
```

### 3.3 ⚠️ 一个必须指出的坑：**λ 的有效强度会被 z 化按 σ(r) 缩放**

`z` 只消掉**总尺度**，**不消掉各分量之间的相对尺度**。所以：

> **λ 不是"直接指定罚项占多大权重"**——它的有效强度是 `λ · σ(â) / σ(目标部分)`。

**这与 §29.1/§32 的"权重失衡在方差"是同一个机制。** 解法有两条：

| | 做法 | 代价 |
|---|---|---|
| **v1（建议）** | **就用 `scalar` 口径**。λ 仍是**单调**旋钮——对偶上升照样把 `â` 推向 `b` | 权衡的**速率**不可控（λ 调多大才够，要试） |
| **v1'** | 罚项作为**独立项** z 化：`A = Σⱼ wⱼ z(−fⱼ) − Σᵢ λᵢ z(âᵢ)` | **依赖 O1**（`adv_mode="per_objective"`），而**O1 还没切成默认** |

**⟹ v1 走 `scalar`。** 但**验收里要加一条**：报出 λ 的收敛值与 `â` 的最终值，
若 λ 需要大到接近数值上限才见效，**说明被 z 化吃掉太多**，那时才动 v1'。

### 3.4 λ 的初值、步长、上界

| | 建议 | 理由 |
|---|---|---|
| `λᵢ(0)` | **0** | 从"无罚"起步；若初值非零，第一组的优势就被污染 |
| `η` | **待定，要扫** | 太大 ⟹ λ 震荡；太小 ⟹ 几百步还到不了预算 |
| **上界** | 有（防发散） | 但**上界不该被触发**——触发即说明标定错了（见 §4） |

⚠️ **λ 是 `joint_chain_step` 的持久状态**（跨步累积），**不是每步重置**。
它要么挂在 `policy` 上、要么由 `runner` 持有并透传。**这是实现上最容易写错的一处。**

## 4. 预算标定：**双侧**

### 4.1 流程（照 ⑧ 交期那一套）

1. 在**参考调度**上测出该约束的**激活量** `aᵢ^ref`（§3.1 的分母）；
2. 选**目标激活率**（如参考档的 50%）⟹ `bᵢ`；
3. **逐实例标定，冻结成表**（像 `TF_RDD`）。

### 4.2 ⚠️ 双侧判据（**`mechanism-designs.md` 原来只有下界**）

| | 防什么 | 判据 |
|---|---|---|
| **下界** | "约束不再咬人"——预算太松 ⟹ `â` 恒低于 `b` ⟹ λ 恒 0 ⟹ **机制空转** | 策略改进 12% 后，`â` **仍不得为 0** |
| **上界** | "约束咬死动作"——预算太紧 ⟹ T3 把策略推向极端 | **该约束对应的动作分布不得退化成单一取值** |

**上界的实例**（这是最容易犯的）：

| 约束 | 预算过紧会把策略推成 | 退化形态 |
|---|---|---|
| **⑪ 充电** | **永远充电** | 与"耗尽模型修复前"的**永远不充**是**反向同一种退化** |
| **⑫ 维护** | **永远保养** | 同上 |
| **① 拥堵** | **永远走最空的路**（哪怕绕远） | 绕路省下的等待 < 多走的距离，净亏 |

**⑪ 那条尤其要盯**：§33 刚把它从"永远不充"救回来，**T3 标定过紧会用另一种方式推回去**。
两者**不能互相抵消**。

## 6. 验收测试

1. **默认关 ⟹ 逐位不变**（黄金摘要）。
2. **λ 恒 0 时 ⟹ 与关档逐位相同**（"罚项没生效"要能被测出来）。
3. **`â > b` ⟹ λ 上升；`â < b` ⟹ λ 下降且不为负**（对偶上升的方向）。
4. **② 的计数两处都记**：构造一个"只有运输侧会阻塞"的场景，断言计数 > 0；再构造只有 AGV 侧的。
5. **⑫ 的拆分**：规则档下 `pm_events_chosen == 0`（规则不会主动提前保养）；
   策略档主动保养时 `chosen > 0` 而 `forced` 不变。
6. **退化守卫（上界）**：跑完后 `⑪ 的充电动作使用率` 落在中间带——**不是 ~0 也不是 ~1**。
