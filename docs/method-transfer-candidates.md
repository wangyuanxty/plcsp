# 可迁移的方法：缺口 → 顶会方法 → 域内已有（2026-10-04）

> **本文回答一个问题**：有哪些 AI 顶会/顶刊的方法可以迁移到生产-物流协同调度（PLCSP）？
>
> **按"我方缺口"排序，不按方法排序。** 能迁移的方法很多，值得迁移的少——
> 判据是**它解不解决我们已知的具体缺口**。

## 0. 判据（先读）

| | **不给分** | **给分** |
|---|---|---|
| 论证 | "没人做过这条" | "**他们做不了这条，因为假设/表征排除了它**" |
| 修法 | 加一个模块 | 修法**可证、可消融** |
| 结果 | 指标更好 | **改变了某条已有结论** |

⚠️ **本仓已因"空隙论证"栽过两次**（`progress-log.md` §12.5 三环节交集、§12.6 跨拓扑迁移）。
本表每一条都要能回答"**为什么别人做不了**"，不能只写"没人做"。

⚠️ **"域内 0 篇"是弱主张**——"第一次用"本身不给分。

## 2. 三条最值得的

**① 动态图 / 边权随状态变（对应缺口 1）**
域内 12 篇自认做不了，**根因是他们把路网当静态拓扑**——GNNT 原文自认
"the model **cannot detect or avoid congestion** that emerges in real time"。
**"让边权随实时争用变"直接命中他们写下的 future work。**

**② 指针网络 / 变长子集输出（对应缺口 3）**
域内 0 篇让策略决定批量。**根因是现有动作空间全是"从定长候选里打分"**，表达不了"这趟带 3 件"。

**③ 约束 RL（对应缺口 2）**
T3 的预算原则已定，**缺的只是把它接到一个已验证的算法骨架上**。

## 3. ⚠️ 一处张力：几何线被砍 vs 域内 12 篇自认缺几何

**本仓 2026-10-02 把几何/度量感知注意力整条砍了**（`progress-log.md` §12.6，
理由是"顶会顶刊提都没提 = 无跨布局泛化需求"）。

**但域内 12 篇自认做不了的那件事，恰恰是"表征里没有几何"。** 这两件事**不完全是一回事**：

|---|---|---|

**⟹ 该砍的是"泛化卖点"，不必然该砍"几何作为 ① 的输入"。本文只记录这个张力，不下结论。**

## 6. 裁定：§2 那三条我们做不做（2026-10-04 定）

### 6.1 三条都做，且**都不改架构**

| # | 做什么 | **不做什么** |
|---|---|---|
| **① 拥堵** | 加 **R2 区段 token**（设计已有）；**恢复几何/度量偏置项**（见 6.3） | ❌ 不换 GNN |
| **② 拼批** | **预构造批次 + 候选打分**（`mechanism-designs.md` §⑩ 已这么设计） | ❌ 不用指针网络 |
| **③ T3** | **奖励加罚项 + λ 对偶上升**（预算原则已定） | ❌ 不加 critic、不换 PPO |

**理由**：这三条各自缺的都不是"网络结构"，是**状态里的量**或**奖励里的项**。
换架构不解决任何一个。

### 6.2 GNN：**不换**

GNN 相对全连接注意力只多三样东西：

| | 本仓需不需要 |
|---|---|
| (a) 结构先验（谁连谁） | 全连接注意力自己学得到 |
| (b) 稀疏省算力 | **不需要**——token 才 20 个 |
| (c) **边上带特征**（距离、实时争用） | **需要，但可以直接做成注意力分数上的偏置项** |

**并且：域内 GNN 已 12 篇。用 GNN 本身不给分，不用也不减分。**
**关键是状态里有没有那个量，不是用什么网络。**

### 6.3 几何/度量感知注意力：**加"输入"，不加"卖点"**

§12.6 砍掉的是**"跨拓扑零样本迁移"这个卖点**——砍得有道理（自有数据亦弱，M7 仅 −7.1%）。
但"几何项"有**两个完全不同的用途**：

| 用途 | 裁定 |
|---|---|
| **卖点**：跨布局泛化 | ⚫ **不加回** |
| **输入**：让拥堵可感知 | ✅ **加回**——这是 ① 的**必要条件** |

**依据**（§1 已记）：域内 12 篇自认做不了拥堵，**根因是表征里没有几何**——
GNNT 原文自认 "cannot detect or avoid congestion"；AEI 103216 连注意力层都没有，
只能把距离写成手写规则。

⚠️ **加回时要写清限定**：只能主张"几何作为拥堵的输入"，**不得**借它主张跨布局泛化。

### 6.4 GRPO：**不换 PPO**

1. **域内 PPO 族 15+ 篇，已用滥**；**GRPO 域内 0 篇**——本仓的差异点恰好在这。
2. **拉格朗日与值函数正交** ⟹ 约束 RL 不需要 critic。"PPO-Lagrangian" 是历史叫法，
   **可做 GRPO-Lagrangian**。
3. 换 PPO 要**引入 critic**，而 critic 在稀疏奖励 + 长 horizon 的调度上难训。

⚠️ **但 GRPO 想立住，必须补一个实验**：**REINFORCE 消融**，证明"组内相对"在这个问题上
**必要**。**"域内 0 篇"不给分**（见 §0 判据）。这是 INDEX §5 高优先第 3 条。

### 6.5 ⚠️ 一条实现上的硬要求

**R2 的区段 token 必须只在 `route_k > 1` 时加入序列。**

否则 token 序列变长 ⟹ **默认档（`route_k=1`）的输入也变** ⟹ **全部既有读数作废**。
本仓纪律是**默认关 ⟹ 逐位不变**。R2 要遵守它，就得是**条件 token**，不是常驻 token。

### 6.7 为什么 ⑩ 与 T3 也必须在冻结前做（2026-10-05 补）

**起因**：用户问"你列的那三条迁移创新机制，加到基线里没有"。核下来 **⑩ 拼批头与 T3 原本
被放在"留作消融"，与 §6.7 那句"基线能全开"自相矛盾**。

**判据**：**论文的头号主张是"我们处理 10 条约束"。头号配置里没有的机制，就不算被方法处理。**
§30.0 的 A 类是"把被规则拿走的决策权交还策略"共 4 条——**⑩ 是其中一条**。

⚠️ **T3 带两个前置**（`mechanism-designs.md` 已记）：

1. **② 的激活指标要新增**——现在**没有"因缓冲满而等待"的计数**（仿真层要加）。
2. **预算表要先标定**——照 ⑧ 交期那一套流程，**不锚参考调度的绝对值**。
   且标定要**双侧**：下界防"约束不再咬人"，**上界防"约束咬死动作"**
   （预算太紧会把 ⑪ 推成"永远充电"，与模型耗尽修复前的"永远不充"是反向同一种退化）。

**顺序**：

1. 实现上表里未做的六项（**R2 · 几何偏置 · ⑨ · ③ · ⑩ · T3**）
2. **冻结**——把"冻结什么"写成清单（设备档、并行度、全部开关、随机流口径）
3. 跑**多实例复现**（MK02–MK10）
4. 之后再加消融项

⚠️ **线划完就不再往里加。** 新想到的一律进消融项，不改这一节。

### 6.8 论文头号配置

**"基线档能不能把所有机制都打开？"——能，而且通常是这么做的。**

标准做法是 **全开 + leave-one-out 消融**（每次关一个，看掉多少）。不需要"基线只留一部分"。

**只有三类真的不能进**：

| 类别 | 例子 | 为什么 |
|---|---|---|
| **互相打架** | T3 若罚"充电次数"，就是**惩罚 ⑪ 头刚拿到的动作**（`mechanism-designs.md` 已记该矛盾） | 要么改定义，要么只留一个 |
| **不针对任何缺口** | **T2 势能塑形**——**只改收敛、不改最优解** | 进基线**不加主张，只加成本** |
| **被证无用** | ③④⑨ 无需机制（§30.0 B 类）；⑤⑧ 靠特征已够 | **③ 已因退化曲线改判**，见 §6.6 |

**⟹ 判据是：它有没有一个可写的 claim。有就进，没有就不进。**

**留作消融的候选**：O3a / O3b · T2 / T5 / A1 · 通用四条（CVaR / 排序损失 / 切比雪夫 / 残差 RL）。
（⑩ 与 T3 已按 §6.7 移入冻结前清单。）
