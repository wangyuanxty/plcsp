## 5.10 ⑧ 交期口径重设计（TF/RDD）——死目标复活（2026-10-03 完成）

- **根因**：旧口径 `d_j = τ·M_ref` 是**共同交期** ⟹ `TWT ≡ 0 ⟺ makespan ≤ τ·M_ref`；实测 30 步训练后
  makespan **89.5 < 0.90×103.4 = 93.1** ⟹ 五组消融 TWT 全 0（`§20.4-2` 的"死目标"是**恒等式**，不是噪声）。
  另一病是**内生**：`M_ref` 取自我们自己的参考调度，换车队规模就换交期（mk01 n_agv=1/3 → 109.95/103.42）。
- **新口径**：`d_j = LB·τ·(1 + R·(2ρ_j − 1))`（TWK 的作业工时 + TF/RDD 参数），
  **外生**（只读实例数据，入口签名里没有 cfg）、**逐作业**、**有跨度**；`LB = max(ΣW_j/m, max_j W_j)`。
  实现 `plcsp/env/due_dates.py`；标定脚本 `plcsp/m16_due_calib.py`（表由脚本产出，测试逐实例对拍）。
- **冻结 (τ,R) 表**（R∈[0.2, 0.8]）：mk01 2.45/0.2｜mk02 2.65/0.3｜mk03 3.40/0.5｜mk04 4.00/0.7｜
  mk05 1.55/0.6｜mk06 5.60/0.2｜mk07 1.90/0.6｜mk08 2.50/0.8｜mk09 2.45/0.8｜mk10 3.00/0.7。
  ⚠️ **本表已作废（P4-B Task 2b，2026-10-03）**——装卸站接入后 makespan 全变，几何口径整表重标：
  mk01 **2.75/0.3**、mk02 2.45/0.4、mk03 3.65/0.4、mk04 5.00/0.7、mk05 1.70/0.5、mk06 5.85/0.6、
  mk07 1.90/0.5、mk08 2.70/0.8、mk09 2.70/0.8、mk10 3.10/0.8（见 `spec §3.5`）。矩阵口径另有一张
  `TF_RDD_MATRIX`（§5.11）。
  10 实例的参考/改进 12% 后误期率都落 [.20,.75]（改进后 .40、mk10 .35）；**10/10 实例的 d_j 逐作业互不相同**。
  （该句描述的是**重标后**的几何口径表——误期率读数同型，数值以 `spec §3.5` 为准。）
- **R 的两条边界理由不同（不得混说）**：下限 0.2 **不是可行性边界**（R=0 只是退化成共同交期，
  违背"逐作业"的既定选择）；上限 0.8 是**硬约束**——`1+R(2ρ−1)` 在 R>1 时越过零点会产出**负交期**
  （实测 mk04 在 R=1.2 下 **−35.2**）。已加 `test_due_dates_are_strictly_positive` +
  `tf_rdd_due_dates` 显式守卫（`due_range ∉ [0,1]` 报错）**双保险**。
- **接线**：`SimConfig.tau` 从"唯一标定值"降级为**覆盖开关**（`float|None = None`）+ 新增 `due_range`；
  `_CFG_KEY_SKIP` 与 `_ref_cfg_key` 都覆盖 `(tau, due_range)`；`compute_due_dates(inst, tau, due_range)`。
  ⑧ 只进目标读数 ⟹ makespan 在任何 (τ,R) 下**逐位相同**（10 实例 × 5 组实测）。
  `due_margin` 是编码器输入 ⟹ **历史训练读数（§20.4 表、P2 的 A 端到端）全部作废**，须重跑才能引用。
- **重跑消融（MK01/30 步/G=8）**：五组 TWT 不再全 0——`Full` 37.2、`−物流` 45.9 是活的；
  `−生产` 的 0 是**跑太快**（Cmax 47.8 < 最早交期 49.98，⑧ 开着）；`−信息`/`None` 的 0 是**按定义**（⑧ 关）。
  ⚠️ 适用边界：绝对交期下，远好于参考的策略**仍会饱和**——论文须写明区间。
- **⚠️ 副作用：奖励权重被这次重设计改变**（`wᵢ = (1/fᵢ^ref)/Σ`，而 TWT 事后按当前交期算）：
  旧口径 `f^ref=(103.42, 7.73, 19.51)` → `w=(0.051, 0.680, 0.269)`（TWT 份额 **26.9%**）；
  现行 `f^ref=(103.42, 7.73, 124.05)` → `w=(0.066, 0.880, 0.055)`（**5.5%**，energy 升到 88.0%）。
  **这是"让 TWT 复活"的定义性后果，不是修正**；要不要重新配平是**研究决定**（另行处理）。
- **⚠️ "误期率落带"是 `cfg` 条件、不是实例属性**：标定写死 `SimConfig()`（n_agv=3），
  换 cfg 会改参考调度的完成时刻 ⟹ 同一个 `d_j` 下的误期率变（实测 mk01 在 n_agv=1：参考 1.00、
  改进后 0.80，**双双出带**）。**交期本身仍外生**（`d_j` 与 cfg 无关）。P4 的 n_agv 1/3/5 扫描
  **必须先重标**。
