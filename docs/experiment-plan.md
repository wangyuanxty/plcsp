## 3. 机时账（**需重测，spec §6.3 的账已废**）

| | spec §6.3（旧） | 现在 |
|---|---|---|
| 每步 | MK01 **3.57 s** / MK10 **15.72 s** | MK01 **0.883 s**（CUDA 主进程 + w=8 CPU worker） |
| 协议 | `m6_flat.py`（800 步，G=4） | `joint_chain_step`（G=8，`route_k=1`） |

⚠️ **两个未知量，跑之前必须实测**：

1. **每 run 的步数**——spec 用 800 步；近期脚本用 300 步（§19.3 实测"~25 步即饱和"）。**待定。**
2. **MK02–MK10 的每步耗时**——只测过 MK01。**MK10 的规模是 MK01 的 2.5 倍。**

**粗估**：按 MK01 的 4× 提速，spec 的 75 次 ≈ 6.0 天 → **约 1.5 天**。
但**实例数与步数都变了**，且 MK10 未实测——**这个数字不可引用**。

## 4. 两阶段（用户 2026-10-05 裁定）

| 阶段 | seeds | 目的 |
|---|---|---|
| **初稿** | **1** | 管线跑通 + **找崩** + 看天花板 |
| **投稿前** | **主对比与 REINFORCE ≥5–10**；**消融可留 1** | 方差 + 检验 |

⚠️ **1 seed 的代价**：无误差棒。`INDEX` §4 现在唯一的硬证据是"−18.5%，**30 种子**"——
1 seed 时**退化成一个点**。本仓统计协议（配对 t 检验、`|Δ| ≥ 2σ/√n`）用不了。
域内对位做法是"**每实例 20 次独立运行 + 独立双样本 t 检验**"（Applied Sciences 2025, 15(13), 6995）。

⚠️ **1 seed 的第一个用处不是数字，是找崩**——多实例复现**从来没跑过**。

| | 为什么 |
|---|---|
| **逐约束 binding 判定**（单列成实验） | **spec §6.2 已否**：逐个 leave-one-out ≈ 195 次 vs 分组 75 次。而且它**不支撑任何 claim**——覆盖表是设计陈述，不是实测；T3 的预算只需"参考调度上的激活量"，是一次直接测量。**"哪些约束咬人"由分组消融回答，粒度够。** |
| **走廊链简化升级**（栅格 A*） | 触发条件 = **审稿人质疑**，不是计划内 |
