# 目标条件化双层架构 —— 设计记录

> **状态**：设计定稿 · **参数已定** · **未动工**。2026-10-08。
> **来源**：Gemini 顶层改造方案（用户转述）→ 本仓逐项核对 → 用户重构下层为三 agent → 参数按推荐拍板。
> **⚠️ 先读 §11（创新评估）与 §12（最小验证）** —— 最新的文献核查改变了本设计的定位与下一步。

---

## 0. 一句话

**顶层每 ΔT 输出三个中间目标 `g`；下层三个 agent（生产 / 物流 / 资源）各自在自己的触发点上决策；四者的信用都来自同一个"从同一状态采 N 个目标"的组相对优势。**

---

## 1. 架构

```
实例 + 布局
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Transformer 编码器（**共享**）                              │
│   token = 机台 · 作业 · AGV · 区段（类型嵌入 + 特征）        │
│         + 最近 K 个事件（滑窗 token）                       │
│   输出 Z_t：逐 token 隐向量                                │
└────────┬──────────────────────────────┬──────────────────┘
         │ 全局池化                      │ 逐 token（**attention 硬掩码**）
         ▼                              │
┌──────────────────────────┐            │
│ 【顶层】π_OA              │            │
│  输出 g_t（3 维 · 分档）   │            │
│  时机：定时器 / 扰动事件    │            │
└──────────┬───────────────┘            │
           │ g_t ───────────────────────┤
           ▼                            ▼
┌──────────────────────────────────────────────────────────┐
│ 下层三个 agent（各自触发点独立）                             │
│  ┌─ PA（生产）── 机台侧 ─────────────────────┐             │
│  │   触发：工序可上机    动作：12 条规则选 1   │             │
│  └────────────────────────────────────────────┘             │
│  ┌─ LA（物流）── AGV 侧 ─────────────────────┐             │
│  │   触发：运输任务生成  动作：3 条规则选 1    │             │
│  └────────────────────────────────────────────┘             │
│  ┌─ RA（资源守护）── 资源生命周期 ────────────┐             │
│  │   充电头：触发 = AGV 待命，动作 = {待命, 充电}│            │
│  │   保养头：触发 = 机台完工且下一件未上机，     │            │
│  │           动作 = {生产, 保养}               │            │
│  └────────────────────────────────────────────┘             │
└──────────────────────────────────────────────────────────┘
           │
           ▼
     段末结算 Y^i  →  A^i = (Y^i − mean) / std
     四个 agent 共用这一个优势
```

**agent 数 = 4（顶层 1 + 下层 3）· critic 数 = 0**

## 2. 四个 agent 的规格

| Agent | 管什么 | 触发点 | 动作空间 | 受 `g` 影响 |
|---|---|---|---|---|
| **OA**（顶层） | 全场运行体制 | 定时器 / 扰动 | **3 维 · 分档** | — |
| **PA**（生产） | **机台** | 工序可上机 | **12**（4 作业 × 3 机台） | ✅ 偏置 |
| **LA**（物流） | **AGV 派车** | 运输任务生成 | **3** | ✅ 偏置 |
| **RA**（资源） | 资源生命周期 | 见下 | **2 + 2** | ❌ |

**PA 的 12 条 = {SPT, EAJ, SRPT, EDD} × {SMPT, MINU, EAM}**
（**EDD 是新增的** —— 原 9 条里没有交期规则，而 ⑧交期是保留约束）

**RA 的两个头：**

| 头 | 触发 | 动作 | 依据的观测量 |
|---|---|---|---|
| 充电 | AGV 待命 | {继续待命, 去最近桩} | 电量、桩占用 |
| 保养 | 机台完工且下一件未上机 | {正常生产, 主动保养} | 役龄 / 保养间隔 |

## 3. 顶层输出 `g_t`

$$g_t = [\ \theta_{wip},\ \theta_{otr},\ \theta_{agv}\ ]$$

| 分量 | 含义 | 观测量 | 覆盖 |
|---|---|---|---|
| `θ_wip` | 在制品上限 | 缓冲区积压 | **约束 ②** |
| `θ_otr` | 目标交期达成率 | 按时完工比例 | **约束 ⑧** |
| `θ_agv` | AGV 周转率目标 | 单位时间完成的运输任务数 | 物流侧产出 |

**全部是比例 ⟹ 尺度无关 ⟹ 换实例定义不变。**

### 注入 —— 统一成一种机制

```
logits(PA 的 12 条) = base_PA(Z_t) + B_PA · g_t      B_PA ∈ R^{12×3}
logits(LA 的 3 条)  = base_LA(Z_t) + B_LA · g_t      B_LA ∈ R^{3×3}
```

**`g` 就是规则打分上的**线性偏置**。`B` 的第 j 列 = "第 j 个目标把哪些规则往上抬" ⟹ 可解释。**

**⚠️ RA 不受 `g` 影响**（资源自省与全场节奏无关）—— 见 §9.3。

### 为什么是"中间目标"

| | 最终目标 | 中间目标 |
|---|---|---|
| 例 | makespan · 能耗 · TWT | WIP · 交期达成率 · AGV 周转率 |
| 何时可知 | **回合末**（稀疏） | **段内可测**（稠密） |

> **顶层的活儿：把期末那个稀疏目标，翻译成段内可执行的稠密目标。**
> **没有这一层，下层只拿得到一个回合末的数 —— 那是信用分配灾难。**

## 4. 组与优势

```
在顶层决策点 t：
  从同一状态 s_t 采 N 个目标   g¹ … g^N
  各跑 ΔT：
      g¹ → 三个下层 agent 各自决策 → Y¹
      ⋮
  ────────────────────────────────────────
  A^i = (Y^i − mean(Y)) / std(Y)
```

| 谁 | 更新式 |
|---|---|
| OA | `logp(g^i) × A^i` |
| PA | `(Σ logp_PA) × A^i` |
| LA | `(Σ logp_LA) × A^i` |
| RA | `(Σ logp_充电 + Σ logp_保养) × A^i` |

**无 critic。**

---

## 5. 训练循环

```
for 每个顶层决策点 t:
    1. 从 π_OA(·|Z_t) 采 N 个 g
    2. N 条链各跑 ΔT（同种子 + 同前置动作，保证起点相同）
    3. 段末结算 Y^i
    4. A^i = (Y^i − mean) / std
    5. 四个 agent 全部用 A^i 更新
    6. 选一条链继续
```

---

## 6. 成本

```
成本 = 顶层决策次数 × N × ΔT = (T / ΔT) × N × ΔT = N × T
```

**⟹ 只由 `N` 决定，与 `ΔT` 无关。** 参照：既有 `G=8` 一步 MK01 实测 18.2 s、MK10 86–94 s。

## 9. 已知问题（诚实记录）

### 9.1 ⚠️ 共享 `A^i`：对下层不是"干净的组"

组的变异有两个来源：`g^i` 不同 + 下层自身采样。

- **对顶层干净**（组就是 N 个 `g`，标准 GRPO）
- **对下层无偏但方差大** —— 基线可以是状态的任意函数，`g` 对下层是状态的一部分 ⟹ 合法；但若 `A^i` 主要由 `g^i` 决定，下层学到的是"哪个 (状态, g) 上下文好"，**而不是"我哪个动作好"**
- **⚠️ 顶层早期探索范围大 ⟹ 稀释最严重时正是下层最缺信号时**

**修法**：加大 N / 双层组（贵）/ 接受。**起步接受，论文须主动说明。**

### 9.2 RA 数据量（已核算，**不是问题**）

| RA 的头 | 每 episode | **每 epoch（×N=8）** |
|---|---|---|
| 保养 | ~40 | **~320** ✅ |
| 充电 | ~10–30 | **~80–240** ✅ |

### 9.3 `g` 到 RA 的因果链断了

**RA 不受 `g` 影响 ⟹ 顶层管不到它。** 说辞：现实里保养/充电不归调度室管（设备科自决）。

### 9.4 「动作空间纯净」的说法要小心

**PA/LA 是"从固定规则集里选"（超启发式），RA 是"做不做"（直接控制）。两者纯净的方式不同。**

### 9.5 ⚠️⚠️ **非稳态：本设计的核心假设被文献部分反证**（2026-10-08 核查）

**原假设**：免 critic 的组相对优势 ⟹ 消除 HRL 的 critic 非稳态。

**反证一 —— HiMAC 的消融（arXiv:2603.00977）**

唯一同时做"免 critic 组相对 + HRL 非稳态"的论文。它把修复归给**交替更新**（Iterative Co-Evolution），**不是**去掉 critic：

> *"To stabilize this bi-level optimization, we introduce an **Iterative Co-Evolution** strategy … ensuring each level is updated against a **stationary counterpart**."*

| 变体（Qwen2.5-7B-Instruct） | ALFWorld | WebShop |
|---|---|---|
| HiMAC 全量 | 92.1 | 84.1 |
| **去掉交替更新**（免 critic 优势**仍在**） | **85.3（−6.8）** | **74.8（−9.3）** |
| 去掉分层（扁平 GRPO） | 77.6 | 66.1 |

**⟹ 免 critic **本身没有**消除非稳态惩罚。**

**反证二 —— 免 critic 在长时程上可能更差**

*Learning Without Critics? Revisiting GRPO in Classical RL Environments* — arXiv:**2511.03527**：

> *"learned critics remain essential for long-horizon tasks: all critic-free baselines **underperform PPO** except in short-horizon environments like CartPole"*

**⟹ 我们的调度 episode 是长时程 ⟹ GRPO 有可能**比 MAPPO 差** ⟹ 整个架构选择有风险。**

**⟹ 处置：见 §12 最小验证 —— 先跑便宜的对照，别急着搭四 agent。**

### 9.6 不能靠"下层固定"论证非稳态不存在

**外部核查把我们的下层误判为 "rule-based / fixed"。** **但 PA/LA 是**学的**（学选哪条规则）⟹ 下层会漂移 ⟹ 经典非稳态**存在**。**

## 10. 已定参数

| # | 项 | **定** | 理由 |
|---|---|---|---|
| ① | **`N`（组大小）** | **8** | 与现有 `G=8` 同级，不增预算；且 N 越大 §9.1 的稀释越轻 |
| ② | **`ΔT`（宏观步长）** | **固定事件数 = 20 个完工事件**（若事件不足则退化为时间上限） | 时间是实例相关的，**事件数把规模归一**；成本与 ΔT 无关，可自由选 |
| ③ | **`Y^i` 合成** | **段内完成工件数 + 段内能耗 + 段内拖期增量** | **三者都是段内可测的真增量**。⚠️ makespan 中途无定义（Shi 2025 在此处含糊）—— **绝不能直接用它**；"完成工件数"当吞吐代理 |
| ④ | **`g` 表示** | **分档：每维 4 档 ⟹ 4³ = 64 个组合** | 目标空间本就粗；分档 logp 简单、好调试 |
| ⑤ | **顶层触发** | **定时器（②）+ 机障 ③ + AGV 故障 ⑨** | 顶层存在的意义之一就是扰动后快速重规划 |
| ⑥ | **观测掩码** | **共享编码器 + attention 硬掩码** | 省参数、稀疏头借共享表征；**论文须写明"分权在决策层，不在表征层"** |
| ⑦ | **实例** | **训练：Brandimarte MK01–MK06（MKT 矩阵口径）· 同分布测试：MK07–MK09 · 跨布局测试：同批实例换布局** | `plcsp/data/brandimarte/Mk*.fjs`；MKT 口径见 `plcsp/env/mkt.py` |
| ⑧ | **基线** | **至少含 MAPPO 版（同架构 · 同编码器 · 同约束）**· NSGA-II · 纯规则派工 | ⑧ 与 §12 的对照是同一件事 |

```
RA·充电  → {AGV token, 桩 token}

```

## 11. 创新评估（**2026-10-08 核查后更新**）

### 11.1 逐件看，没有一件是新的

| 层 | 出处 |
|---|---|
| 子目标 HRL | FeUdal RL（Dayan & Hinton 1993）· FeUdalNets（Vezhnevets et al. ICML 2017）· HIRO（Nachum et al. NeurIPS 2018） |
| 宏观步 | options framework（Sutton, Precup, Singh 1999） |
| 下层规则选择 | selection hyper-heuristic（Burke et al. JORS 64(12):1695–1724, 2013） |
| 组相对优势 | GRPO（DeepSeekMath, 2024） |
| 异构 token Transformer | 标准 |

### 11.2 ⚠️ 核查结论：**部分是已发表的**

| 我们的元素 | 状态 |
|---|---|
| **GRPO + 分层策略** | ❌ **已发表** —— **HiMAC**（arXiv:2603.00977）· **Hi-Agent**（arXiv:2510.14388 / iFuture 2026） |
| **"从同一状态采 N 个做组归一化"** | ❌ **已发表** —— **GiGPO**（**NeurIPS 2025**, arXiv:2505.10978）的 *anchor state grouping*："Actions stemming from the same state are grouped together" |
| GRPO 出 LLM 圈子 | ❌ 已发表（机器人控制 · MARL · 组合优化） |
| **跨层共享一个优势** | ✅ **未找到**（HiMAC / Hi-Agent 都是**各层各自**的优势） |
| **非 LLM / 调度域的分层 GRPO** | ✅ **未找到** |
| **options / macro-action 框架下的 GRPO** | ✅ 未找到（arXiv `"macro-action"`=0、`"temporal abstraction"`=0） |
| **"免 critic 消除 HRL 非稳态"** | ❌ **未找到，且被部分反证**（§9.5） |

### 11.3 剩余可辩护的

1. **非 LLM / 调度域的实例化** —— 只是应用
2. **跨层共享优势** —— 未被占，但**要能说清它好在哪**（目前只是"没找到别人这么做"）
3. **措辞空间** —— options / macro-action 框架下的 GRPO
4. **RA 这个第三 agent** —— 结构上的新意，未核

**⟹ 四条里没有一条够"发现"级别。**

### 11.4 评分

**方法新颖性 低 · 发现新颖性 低（原判"中"已下调） · 域新颖性 低 · 工程完整度 高**

**⟹ 约当一区应用论文。**

**另一条路（暂缓）**：约束处理在高层 —— 唯一有外部文献证据的缺口
（Juárez et al. *AI Review* 59(2):80, 2026 §5.1.6 明说 open；21 种措辞 × 13,456 条记录扫描，约束激活报告零命中）。

## 12. ⭐ 最小验证（**动工前的第一步**）

**§9.5 那条风险是硬风险**：若 GRPO 在长时程上确实不如 PPO，**整个架构选择的理由就没了。**

**⟹ 先用**最便宜**的方式测掉它，别搭完四 agent 才发现跑不动。**

| | |
|---|---|
| **不搭分层** | 用现有 `joint_chain_step` 即可 |
| **不搭三 agent** | 只换优势估计器 |
| **臂 A** | `A = GAE(回报, V(s))`（**加一个 critic**） |
| **臂 B** | `A = (R − mean)/std`（**现行 GRPO**） |
| **其余** | 完全相同：同实例 · 同编码器 · 同约束档 |
| **种子** | **多种子**（单种子说明不了稳定性） |

**测三样**：训练曲线方差 · 收敛速度 · **扰动（③⑨）下的最终业绩**

**判据：**

| 结果 | 下一步 |
|---|---|
| **B 明显差** | ⚠️ **架构方向要重想** —— 不能先搭四 agent |
| **B 不差（或更好）** | ✅ 再往上搭分层 |

**⚠️ 这一步比搭四 agent 便宜一个数量级。**
