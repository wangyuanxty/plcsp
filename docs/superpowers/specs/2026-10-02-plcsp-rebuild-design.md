## 1. 问题定义

**生产-物流协同调度（production-logistics collaborative scheduling problem, PLCSP）**，
**两环节**联动：

```
排产（flexible job shop：工序-机器分配与排序） → 物流（AGV 派车）
```

- **问题类**：FJSP（作业车间，每工件多工序、有机器柔性）+ 真 AGV 派车
- **术语**：主词用 PLCSP（引 AEI 65:103216 李新宇组 / AEI 65B:103195 同济）；
  related work 中同义引入 `integrated scheduling of machines and AGVs`（该线谱系更长，可追至 Ulusoy & Bilge 1993, IJPR 31(12):2857-2873）
- **边界声明**：RL 控制**任务分配**（工序-机器分配 + AGV 派车）；局部避障（毫秒级）交由 AGV 车队系统（RCS）/厂商控制器托管

### 1.1 不做的事（明确排除）

| 排除项 | 理由 |
|---|---|
| 分批 / 投放门控 | 顶刊 PLCSP 基本无此概念；自有实证"非杠杆"，且文献支撑系偷换概念（见 §2） |
| 几何/度量感知注意力 | 用户判断"顶会顶刊提都没提 = 无跨布局泛化需求"（见 §2） |
| 跨布局零样本迁移 | 同上 |
| 布局 × 策略共演化 | 实证平局，且最优解退化到边界角点 |

### 3.2 布局——**二维网格**（2026-10-02 定案，取代 line/U/island）

**形态来源**：**AEI 103216 Fig. 2**（原文："This paper adopts the layout of shop floor in **[5]**"）——即 **Cai et al., IJPR 61(4):1373-1393, 2023**。该图形态为：**机台排在二维格子里，通道是格子之间的格线，AGV 沿格线走，装卸单元在网格外一侧。**

> ⚠️ **引用注意**：AEI 103216 **不自带布局定义**，它借用 [5]。我们的 related work 若提"采用与 AEI 103216 同形态的车间布局"，须同时引 **[5] Cai et al. 2023**。
> ❌ **不要引 JMS 82（MMSLS, Zhu/Liu/Tongji）作为布局来源**——该文经核**不是物理平面图**：`aisle` 0 次、`travel` 0 次、`AGV` 仅 2 次；其 "matrix" 指 **工作站-位置的分配矩阵**（n × m × m），无运输建模。

#### 结构定义

```
机位网格：n_rows × n_cols（n_cols = ceil(√n_m)，n_rows = ceil(n_m / n_cols)）
          机台占格；空格允许（MK07 的 5 台机放进 3×2 网格 → 1 空格）
通道格线：节点 = (n_rows+1) × (n_cols+1) 个交叉口
          边 = 相邻交叉口的横/竖线段，权重 = 段长 [m]
机台 dock：每台机接到其所在格四角**最近的通道节点**
充电桩：≥2 个，落在不同位置的通道节点上（决策 = 何时充 + 去哪个桩）
装卸站（LU）：**格点外的新节点**，由一条**连接段**接到左边缘交叉口（P4-B Task 2b 接入）
             作业在站入场、完工回站；`task_flow` 的端点号 = 机台 `0..m-1`、装卸站 `m`
```

**关键性质**：**通道在格子之间，机台在格子之内 → 通道不会穿过机台**。`corridors.py` docstring 自陈的 v0 缺陷（"连线在几何上可能穿过机台矩形，无净空判定"）**在本布局下自动消失**，无需栅格 A* 即可保证连通可行。

#### 区段：**已按参数化粒度恢复**（2026-10-02 更正）

> ⚠️ 本节此前写"区段已无此概念"——那是 ① 被误砍时期的旧口径。**① 已于 `eb1d1da` 恢复**，
> zone 管制与死锁检测随之一并回归，粒度可参数化（`node`/`row`/`col`/`all`）。
> 详见 §3.3.1 与 §3.3.2 的 binding 判定。

网格布局的价值不变且更突出：**通道在格子之间 → 不穿过机台**，故无需栅格 A* 即可保证连通可行。

#### 与旧设计的关系

| 旧 | 新 |
|---|---|
| `line` / `U` / `island` 三种一维拓扑 | **单一网格形态**，参数化（`n_rows, n_cols, cell_w, cell_h, aisle_w`）|
| 走廊图 = **单环**（相邻 dock + 首尾闭环） | **二维格点图**（横竖边）→ 距离更真实，且连线不穿机台 |
| 距离矩阵 = 环上最短路 | 距离矩阵 = **格点图最短路**（Dijkstra）|

**布局类型不再是实验维度**（跨布局泛化已砍，spec §1.1）。敏感性参数改为 **`aisle_w`**（→ `eff_speed` 窄道降速）与 **网格长宽比**。

#### 连带影响：**已复测结案**

line 上的拥堵数据（32%）与"加车更慢"的机制候选，**换网格后全部不成立**——见 §3.3.1。
`n_agv` 已按新判据重标（§6.3）。

#### 行程时间口径（P4-B，2026-10-03）

**共存规则（用户裁定）：口径跟随实例，不是全局开关。** 原始 MK 实例走**几何口径**（格点最短路
÷ 有效车速 ÷ 60，现状数字不变）；MKT 实例走**机台间行程时间矩阵**（`plcsp/data/mkt/`）。
矩阵作为**实例数据**挂在 `Instance` 上（`transport` 标签 + `trans_time_full`），故
`rollout` / `SimWorld` / `build_setup` / `reference_run` / 训练栈的**签名一概不变**，矩阵口径
自动贯通。任何"全局开关"都允许**同一实例跑出两套行程时间**——那是静默错配；口径是**问题的
属性**，不是运行配置（`SimConfig` 里不得出现口径/矩阵开关，`test_transport_wiring.py` 钉住）。

实现：`plcsp/env/transport.py::TransportCaliber`（几何 / 矩阵两态，不可变；单一汇合点
`AgvSim._leg_min`）。

**矩阵口径的三条硬约束**（都来自数据本身，见 `plcsp/data/mkt/README.md`）：

1. **矩阵已经是分钟**——**不得**再套几何口径的 `距离 / (eff_speed · 车速) / 60` 换算。
   `agv_speed_mps` / `aisle_width` 在矩阵口径下**不改变行程**（有测试钉）；车队内部的
   **相对**速度倍率（⑩）仍生效。
2. 原始矩阵是 `(m+1) × (m+1)`，**第 0 行/列是装卸站（LU）**，机台 i ↔ 下标 **i+1**。
   口径对象只接受**含 LU 的全矩阵**；喂进 `load_mkt_layout(m)` 的默认（已丢 LU）结果会**显式报错**。
3. 矩阵**非对称**（`m=4` 是唯一例外）⟹ 查表**必须保序**（有实测非对称项钉住）。

**装卸站（LU）已接入**（P4-B Task 2b）：**格点外的新节点 + 一条连接段边**，不是被复用的边界
交叉口（那会静默短掉一整段连接段）。作业在站入场、完工回站，两端各一条负载段走正常派车路径；
`completes[j]` 由**到达装卸站**的时刻给出。故矩阵的第 0 行/列**今天有消费者**，我们的 makespan
**含回站运输**（P4-A 的"不含回库运输"告诫已作废）。

**未映射端点（充电桩）的两种策略**：`SimConfig.transport_unmapped='raise'`（默认，显式报错）
或 `'geometry'`（**声明式**几何降级为几何口径，段数与分钟数随 metrics 带出）。**报告档 B
用的是后者**——论文必须如实声明"这一报告档里有 x% 的行程是几何口径补的"（实测 mk10 报告档 B 为
**2.62%**、mk07 **0.67%**、mk01 **0.078%**），不得说成"运输全部来自矩阵"。

**① 开时区段拆分**：矩阵里没有"中间走廊节点"这一说，故**整段时长先查表算出**，再按各段的
**几何占比**摊到逐段（占比之和恒为 1 ⟹ 各段之和**逐位等于**矩阵查表值，有测试钉）。

**读数总结（论文"约束重要性"一节的数据基础）**：

1. **只有 ⑤ 换型在默认参数下就 binding，且是最大杠杆**（关掉 makespan −28% / −14%）。
   原因：`setup_min_default = 2.0 min` 相对 MK01 平均工序 2.78 min 是**同量级**。
   ⚠️ 该参数是 **assumed**，是**一阶敏感性对象**。
2. **③ ④ ⑨ ⑫ 同型：默认参数下不 binding，极端参数强 binding**（+13% … +900%）。
   **这是"参数尺度不匹配"，不是"机制无关"**——P1a 的教训（用期望次数粗估会错）在此被四次复现。
3. **① ⑩ ⑪ 关态与极端参数下都不 binding ⟹ 本工况下真的无所谓**（**⑥ 因此被砍**，见下）。
   - **①**：与 §3.3.1 的边界扫描一致（争用对运输负荷敏感，但现实车速下 <0.4%）。
   - **⑪**：**结构性死约束**——一个 episode 的 AGV 总耗电仅约 0.27 kWh，而电池 2–4 kWh，
     **放掉不到 20%，连阈值抬到 80% 都触不到**（关态实测**恰好 0.00%**）。
     缩电池到 0.3 kWh（比现实小 7–13×）才勉强动 2%。
4. **共同根因（已在 §3.3.3 展开）**：本工况下**运输不在关键路径**、**机台利用率仅约 25%**，
   松弛把大多数扰动的效应吸收掉了。

> ⚠️ **P4-B 口径条件（2026-10-03，必须并读）**：本节的 binding 判定全部在**几何口径**

#### 3.3.1 ① 拥堵：**机制保留，binding 边界已测**

**机制**：`ZoneManager` —— **区段一车互斥 + 等待环检测**（经典 AGV 死锁的防法）。
AGV 沿最短路**逐段申请**（持当前 → 申请下一 → 成功才放上一 → 走这一段）。
**区段粒度是参数**（`SimConfig.zone_granularity`）：`node`（每路口，**默认**）/ `row` / `col` / `all`。

**扫描 A — 粒度**（MK10，4 车，车速 1.0 m/s）：

| 粒度 | 区段数 | 争用 |
|---|---|---|
| node | 25 | 0.02% |
| row | 5 | 0.06% |
| col | 5 | 0.03% |
| **all（全图互斥）** | **1** | **0.15%** |

**扫描 B — 运输负荷 × 车队规模**（MK10，5 种子）：

| 车速 [m/s] | 2 车 | 4 车 | 8 车 |
|---|---|---|---|
| 1.0（默认）| 0.013% | 0.011% | 0.010% |
| 0.5 | 0.037% | 0.038% | 0.029% |
| 0.2 | 0.306% | 0.322% | 0.195% |
| **0.1** | **1.78%** | 1.28% | **0.872%** |

**两条结论（都要写进论文）**：

1. **争用随运输负荷单调上升**——车速 1.0 → 0.1（运输时间 ×10），争用 **0.013% → 1.78%，涨 137 倍**。
2. **但对车队规模不敏感，且加车使其略降**——同负荷下 2/4/8 车 = 1.78% / 1.28% / 0.872%。
   原因：**"同时在动的车数"由运输需求决定，不由车队规模决定**；加车只制造闲置，不制造拥堵。

**定位**：在 Brandimarte 标准实例的现实参数下（AGV 利用率 ≤22%），争用 <0.4%——**不 binding**。
要复现高争用需利用率 >100%（运输成为瓶颈），那时"任务排队"已是主要矛盾。

### 3.5 交期

**原设置已废弃（两条，按时间顺序）**：① `d_j = 1.8 × 作业自身总加工时间` —— **完全没算排队/运输/争用**，实测 MK01 上 makespan=405 而交期仅 16–40，**tardy ≡ 10/10，目标退化无信号**。② `d_j = τ·M_ref`（共同交期，锚在**自己的**参考调度上）—— **内生**：换车队规模就换 `M_ref`（实测 mk01：n_agv=1/3 → 109.95/103.42，交期跟着漂），且**结构性退化**：

```
TWT ≡ 0   ⟺   makespan ≤ τ·M_ref        （d 全同 ⟹ TWT 只取决于 max_j C_j 与 d 的大小关系）
```

实测（`progress-log §20.4`，30 步训练后的策略）：makespan **89.5 < 0.90 × 103.4 = 93.1** ⟹ **五组消融的 TWT 全为 0.0**，三目标实际退化成两目标。这不是初始化噪声，是**恒等式**。

**现行设置（TF/RDD 形式，2026-10-03 定案）**：

```
W_j  = 作业 j 各工序最短候选工时之和        # total work content（TWK），纯实例数据
LB   = max( Σ_j W_j / m ,  max_j W_j )     # 负荷下界：≤ 任何可行调度的 makespan
ρ_j  = W_j 升序排名归一化到 [0, 1]          # 排名比例；n_jobs = 1 时取 0.5
d_j  = LB · τ · ( 1 + R · (2ρ_j − 1) )     # 逐作业、外生、有跨度
```

**R 为什么限制在 [0.2, 0.8]**（两条理由不同，不得混说）：

- **下限 0.2 —— 不是可行性边界**。R=0 只是让交期退化成**共同交期**（所有作业同值），而"逐作业、有跨度"是本口径的**既定选择**（`due_margin` 维的区分度也依赖它）。⚠️ 早先记录里"mk10 无 R 不可行"的说法**是错的**——R=0 在 τ∈[2.70, 2.90] 就落进速率带；那是把 `τ·W_j` 与 `τ·LB` 两种参数化混为一谈得出的。
- **上限 0.8 —— 硬约束（正数）**。`1 + R(2ρ_j − 1)` 在 **R > 1** 时最低倍率**越过零点**，会产出**负交期**（实测 mk04 在 R=1.2 下最短作业 **−35.2**）。上限 0.8 ⟹ 最低倍率恒 ≥ 0.2 > 0。`tf_rdd_due_dates` 另有显式守卫（`due_range ∉ [0, 1]` 即报错；⚠️ 边界 **R=1.0** 恰给出 `d_min = 0`——非负但已退化，冻结网格取 0.8 上限正是为了避开它），`test_due_dates_are_strictly_positive` 逐实例钉住。

**跨实例 τ 差 3.6 倍（1.55–5.60）**是 TWK 类口径的固有代价，**论文必须如实写**——交期紧度本身就随实例变，不能报一个统一的 τ。

**书目**：TWK 类交期已引证：**《Real-time scheduling for production-logistics collaborative environment using multi-agent deep reinforcement learning》**，Advanced Engineering Informatics（Elsevier），Vol. 65, 2025, Article 103216，DOI 10.1016/j.aei.2025.103216（其式 3 为含物流因素的 Total Work Content 形式）。⚠️ **「TF/RDD」这组命名与参数组合 (τ, R) 的出处待核**——本节的生成式是**基于工时的排名的展开**，**不是**已核文献里的标准 TF/RDD 交期生成器（常见形式是 `d_j = 到达时刻 + TF × 某工时量` 之类）；三个词各自在文献里有明确所指，但**本项目的这个组合方式**未见于已核文献，**不得反过来当作"文献标准做法"引用**。未取得原文，不编造；登记为开放项。

**⚠️ 适用边界（实测，论文必须写明）**：交期是**绝对**阈值——策略一旦好过**最早**的那个 `d_j`，TWT 仍会恒 0。标定规则里的"改进 12% 不退化"只把饱和点钉在**参考附近**。实测 mk01：`Full`/`−物流` 两消融组（Cmax 83.6/81.4）TWT 非零，而 `−生产` 组 Cmax 47.8 **低于最早交期 49.98** ⟹ 整组 TWT ≡ 0（⑧ 开着，不是定义使然）。见 `progress-log §21.5`。

**⚠️ 变更影响（必须带进 P4-B）**：`due_margin` 是编码器输入 ⟹ 交期一改，**策略输入就变了** ⟹ 所有历史训练读数（`§20.4` 的消融表、P2 的 A 端到端）**都不可再引用**，须重跑后才能写进论文。

## 4. 目标与奖励

### 4.1 三个目标

**makespan + energy + tardy**

| 目标 | 说明 |
|---|---|
| makespan | 必选，一切对比的锚 |
| energy | 选它 → **模型必须按 §3.4 M2 做实**（"报告指标"可以糙，"优化目标"不行）|
| tardy | **用加权总拖期 TWT = Σ wᵢTᵢ**，非计数（文献标准形式；且连续，与多目标 Pareto 配合更好）|

**被否的候选**：拥堵度（`requeue`/`trans_evt`，现成且是差异化点）—— 用户选择标准三件套。

### 4.2 奖励（A 打底）

**加权标量化**：`r = w₁·(-makespan) + w₂·(-energy) + w₃·(-TWT)`

- GRPO 是**组内相对**，绝对尺度被组归一化消掉 → 权重只需相对合理
- **签名预留 `prefs` 参数，A 阶段传固定权重**（零成本，为 C 铺路，避免返工）

**权重如何定（不可含糊——权重决定落在哪个 Pareto 点）**：

```
wᵢ = 1 / fᵢ^ref        fᵢ^ref = 参考运行（§3.5 的参考调度：每工序取最短候选 + AGV 轮询）下第 i 个目标的实测值（TWT 按 §3.5 的 TF/RDD 交期事后算）
```

即**按参考调度归一化后等权**——标准做法，物理含义清晰（"相对参考调度各改进一个单位，贡献相同"），且**可复现**（不依赖拍脑袋）。
实际训练用 `wᵢ / Σwⱼ` 归一化。
**该权重向量须与参考调度口径（`M_ref`）及交期表 (τ,R) 一同写进论文实验设置**——否则 TWT 不可复现。

**（若做 C）**：权重向量即偏好向量 λ，按 §4.4 的约束**组内固定、跨组变化**。

### 4.3 被否的方案（记此备查）

**通道化多目标**（每目标各自组内 z 化后等权求和，与 MO-GRPO / Multi-GRPO 的 reward-grouping 同构）—— `m6_opt_a` 实测**更差 +4.3%**。⚠️ 该数字产生于 bug#12 期，不可引用；但其**理论论证**（"组内相对已把奖励尺度消掉，无需再分通道"）不依赖实例，仍成立。

### 4.4 C（偏好条件化）——**延后，不是当前范围**

**前提**：先做通 A。A 跑通后再决定 C 值不值得做。

**已知占用情况（2026-10-02 精读核出）**：**DCAN**（*Neural Multi-Objective Combinatorial Optimization for Flexible Job Shop Scheduling Problems*, **ICLR 2026**, Smit/Wu/Troubil/Zhang/Nuijten, `openreview.net/forum?id=YAgOaYedLQ`）已做"偏好条件化 + 单策略出整条 Pareto + 打赢 NSGA-II/MOEA/D"，**且开源**。

其机制（读 `third_party/Neural_MO_CO_FJSP/` 源码核出）：
1. **FiLM 调制**：`h' = h × γ(pref) + β(pref)`（`model/mo_attention_layer.py:44-45, 224-225`）
2. **双向虚拟节点**：工序 attend 到 {前驱, 自己, 后继, **偏好**}，且**偏好也 attend 回所有工序**（`:54-97`）
3. **偏好每层自我更新**（非静态向量）（`:97, 273-274`）
4. 机器侧把偏好**硬插一行**，连竞争矩阵都扩一行一列（`:230-259`）

**两条对照基线**：`ENC_WEIGHT_INPUT`（偏好作朴素编码器输入）、`HYPER_DANIEL`（超网络）。

**⚠️ DCAN 用加权和，不是切比雪夫**（`mo_train.py:219-222`，注释原文 "Use weighted sum"），理由是**步进奖励的可加性对齐**（`Σ_t λᵀr_t = λᵀΣ_t r_t`；切比雪夫的 `max` 不可加）。
**但我们的奖励是期末结算**（无中间奖励），可加性问题不存在 → **切比雪夫可用，且能覆盖非凸前沿**。这可能是差异点，但要先测真实 Pareto 前沿有无非凸段。

**若做 C，则必须**：偏好**组内固定、跨组变化**——GRPO 的优势是组内相对，同组各链用不同偏好会导致"苹果比橘子"（与当年 SA-GRPO 树倒掉同因）。

## 5. 骨架

### 5.1 编码器（E1：标准 Transformer）

- **去掉**：`GeomBias`（几何偏置）、轴向掩码、`dist`/`conf` 输入参数
- **保留**：`[机台 M | 工序 B | 车辆 V]` **token 分段 + 类型嵌入**，注意力**全连接**
  - 理由：**分段是信息（哪些 token 是什么），轴掩码是限制（谁能看谁）**——去限制不等于去信息
- 2026 风向佐证：表征极简化、Transformer 取代 GNN（RESCHED@ICLR'26、RL-SPH@ICML'26）——**标准 Transformer 是顺势，不是降级**

### 5.2 算法

**flat GRPO**（组内相对、全局 z），非树式、非分层。

**单智能体多头**（2026-10-02 定）——`PolicyNet` 一个网络、**两个头**：

| 头 | 决策 | 对应 |
|---|---|---|
| `mach_logits` | 每工序选哪台机 | S 层（排产）|
| `agv_logits` | 每个运输任务派哪台车 | L 层（物流）|

> 🔻 **`route_logits`（路线头）已取消**：它只为"绕开拥堵"而存在，而 ① 拥堵已砍（§3.3.1）——
> **无拥堵时选远路严格更差**，路线不构成决策。`k_shortest_paths` / `route_phi` 一并从环境中移除。

**为什么是单智能体而非多智能体**（三条理由，按强度排）：

1. **GRPO 是单策略算法**：组内相对优势假设"同组样本来自同一策略、同一状态"。拆成多智能体后每组样本来自不同策略，**组内比较即为苹果比橘子**——与当年 SA-GRPO 树倒掉同因（"组内方案在联合空间中互相不可比"）。
2. **自有实测反对解耦**：`progress-log` §七 记录"L（物流）环节在**随机计划**下无信号（568.4 / 568.2）"——**物流策略的好坏完全取决于排产给的计划**，环节强耦合，独立训练不成立。
   > ⚠️ **2026-10-03 增补**：这条实测有**两个竞争解释**，此前只写了第一个。
   > (a) 环节强耦合（原解释）；(b) **L 头对生产侧结构性失明**——见 §5.3.1 的"接缝未接"：
   > L 头吃的是 11 维手搓向量，**不走编码器**，看不到机台状态、计划、布局，`n_agv≥3` 时
   > 也看不到 2 号以后的车。**一个看不见任何东西的 MLP 当然学不动。**
   > 两者不互斥，但**在 §5.3 的表征接通之前，(a) 无法与 (b) 分离**。
3. **文献里单/多各半**（核心 40 篇：明确多智能体 12 / 明确单智能体 14 / 未写明 12）——多智能体非必须，选了要付信用分配的代价（如 TAAGNet 专门设计"分离式贡献奖励"）。

**任务索引约定**：`agv_phi[task_i]` 按 transporter 生成序（第 task_i 个运输任务）索引，
是所有 L 层派车决策的载体。

**结构**（P2 目标）：一个 `PolicyNet`、**一个编码器**、两个头**读同一份 token 嵌入**。

```
                                    ┌─ S 头 mach_logits_emb(tok[cand], feat_op)
(tok (N, F_MAX), seg) → Linear(F_MAX→d) + 类型嵌入 → 标准 Transformer → (N,d) ─┤
                                            （全连接，E1）                    └─ L 头 agv_logits_emb(tok[cand_v], feat_task)
```

**输入是单张张量**：四段各自的 per-token 特征向量**补齐到同一宽度后按序列拼接**。

```
F_MAX = 10                      # = max(7, 8, 10, 3)
M 段：列 0..6 有效，7..9 补零        B 段：列 0..7 有效，8..9 补零
V 段：列 0..9 有效（无补）            G 段：列 0..2 有效，3..9 补零
```

> **为什么用统一宽度而不是分段投影**（2026-10-03 定）：单 Linear 的参数是 `10×128 = 1280`，
> 分段投影是 `(7+8+10+3)×128 = 3584`——**少 64%**，在 MK01 这种小实例上方向正确；且接口只有
> 一个张量，代码路径唯一。
>
> ⚠️ **代价与前提**：四段的列**语义重叠**（第 3 列在 M 段是"在加工"、在 B 段是"已完成"），
> 故**类型嵌入在此方案下是【必需】而非可选**——它是把重叠列解耦开的唯一手段：
> `machine 嵌入 = W[:,3]·busy + type_emb[0]` 与 `job 嵌入 = W[:,3]·finished + type_emb[1]`
> 靠不同的 `type_emb` 才分得开。**去掉类型嵌入，本方案即失效。**
>
> 📌 **备选（若串味被实测证明有害）**：改用**分块列**（M→0..6、B→7..14、V→15..24、G→25..27，
> `F_MAX=28`）——列不重叠、零串味，但参数回到 3584 且 65% 的列恒零。届时再换，改动仅限
> `features.py` 的列偏移与 `F_MAX`。

**① 三类 token 的字段**（归一化一律用**实例静态量**，见 §5.3.2）

| M（机台，`F_M`=7） | 维 | 依据 |
|---|---|---|
| 输入队列积压 = Σ 队列内工序加工时长 ÷ 实例总工时 | 1 | 该机何时能开工（最强信号）|
| 队列件数 / `in_cap` | 1 | ② |
| 输出缓冲占用 / `out_cap` | 1 | ② 阻塞源 |
| 在加工? + 当前剩余时长占比 | **2** | 排队判断 |
| 距下次保养余量 `1 − pm_clock/pm_interval` | 1 | ⑫ |
| `fail_rate` ÷ 实例内最大 | 1 | ③ |

| B（**作业**粒度，`F_B`=8） | 维 | 依据 |
|---|---|---|
| 已完成工序数 / 总工序数 | 1 | 进度（**需新增追踪**）|
| 剩余工序标称时长之和 ÷ 实例总工时 | 1 | 剩余工作量 |

| 当前所在机台（未开始 = −1）÷ `n_m` | 1 | 位置 |
| 是否在运输中 + 在途车号 ÷ `n_agv` | **2** | 生产-物流耦合的直接读数 |
| 权重 `w_j` ÷ 最大权重 | 1 | TWT 口径 |

> ⚠️ **粒度**：`seg=(n_m, n_jobs, n_agv)`，B 段是 **n_jobs 个作业 token**，不是工序 token。

| V（车辆，`F_V`=10） | 维 | 依据 |
|---|---|---|
| 空闲/空载/负载/故障 one-hot(4) | **4** | ⑨ |
| 当前节点坐标 (x, y) ÷ 车间包围盒边长 | **2** | 派最近的车 |
| 在途任务数 ÷ 实例最大 | 1 | 负载 |
| 电量占比 | 1 | ⑪ |
| 载量 / 容量 | 1 | ⑩ 多载量 |
| 车速倍率 ÷ 最大倍率 | 1 | ⑩ 异构 |

| **Global token（1 个，`F_G`=3）** | 维 | 依据 |
|---|---|---|
| 时间进度 `now / M_ref` | 1 | 策略不知"现在到什么时候了" |
| 完成作业数 / `n_jobs` | 1 | 全局进度 |

> **宽度**：四段字段数为 `7 / 8 / 10 / 3`，补齐到 `F_MAX=10`；全序列 `N = n_m + n_jobs + n_agv + 1`。

故 S 头的候选特征里显式放 `setup_matrix[prev_job_of_m][j]`。理由：⑤ 是实测最大杠杆（−26%），

**③ 归一化用实例静态量**（总工时 / `M_ref` / `n_m` / 包围盒对角线）。
**不用**老设计的 "per-episode normalization"——在线决策下不可得（推理时不知道整段 episode 的统计量）。

#### 5.3.3 奖励与回报

```
r = w₁·(−makespan) + w₂·(−energy) + w₃·(−TWT)
wᵢ = (1/fᵢ^ref) / Σⱼ(1/fⱼ^ref)          fᵢ^ref = 参考调度下的第 i 个目标实测值
```

- **期末一次性结算**，无中间奖励（→ §4.4 的切比雪夫可加性问题不存在，C 阶段可用）。
- `f^ref` 与 `M_ref` **同一次参考运行**取出并缓存（口径一致、只跑一次、可复现）。
- **保留 `prefs` 形参**，A 阶段传固定权重（为 C 铺路，零成本）。
- **现状** ✅ **已解决（2026-10-03，Task 6）**：`env/reward.py` 的 `objective_vector` /
  `reward_weights` / `scalar_reward` / `ReferenceObjectives.of` 实现全部三目标与权重口径
  （`f^ref` 与 `M_ref` 同一次参考运行；TWT 事后按 **TF/RDD 交期**（`due_dates.due_dates_for`）从同一次运行的 `completes` 算）。
  MK01 实测（**2026-10-03 ⑧ 重设计后重测**）`f^ref = (103.42, 7.73, 124.05)` → `w = (0.066, 0.880, 0.055)`。
  ⚠️ **旧值已作废**：`f^ref = (103.42, 7.73, 19.51)` → `w = (0.051, 0.680, 0.269)` 是**旧交期口径**（`d_j = τ·M_ref` 把 TWT 压死）下的读数。交期换成 TF/RDD 后 TWT 从 **19.51 涨到 124.05**，因为 `wᵢ = (1/fᵢ^ref)/Σ`，**TWT 的奖励份额从 26.9% 掉到 5.5%、energy 升到 88.0%**——这是"让 TWT 复活"的**直接后果**，不是笔误。⚠️ **该失衡是否需要重新配平是研究决定，另行处理**；本节只记录事实。由 `test_reference_weights_are_pinned_to_the_due_date_caliber` 钉住，口径再变即红。
  **改前**：`rollout_evaluate` 只返回 `−makespan`；三目标与权重口径**均未实现**。

#### 5.3.4 训练：**联合链 GRPO**（Q1(a)）

**一条链 = 一个完整 episode 的全部决策**：

```
链 = (机台计划序列 a_S[1..n_ops]) ⊕ (派车序列 a_L[1..n_tasks])
logp(链) = Σ_t log π_S(a_S[t]) + Σ_t log π_L(a_L[t])        ← 两条都取【求和】
```

后接标准 GRPO：**一个**终端奖励 `r` → 组内 z 化（`_z`，默认 `z`）→ REINFORCE 或 PPO-clip。

**五条硬性约定**（对应本轮裁定）：

| # | 约定 | 理由 |
|---|---|---|
| 1 | **联合链、单一优势** | spec §5.2 已定单智能体；两头读同一编码器才叫"联合"（§5.3.1）|
| 2 | **logp 一律取求和** | 现状 S 用 `Σ/n`（平均）、L 用 `Σ`（求和）——同一个 `ratio=exp(Δ)` 在两边含义不同，clip 对单决策的约束强度**差 n 倍**（MK10 的 n=240）。统一为求和后 `ratio` 才是链概率比 |
| 3 | **J=1，预算全给 G** | 组内 z 已是相对比较；J 个种子取均值是**组内再降噪**。同算力下 G:8→32 信息量大于 G=8,J=4。J>1 留给**评估**用，不混进训练 |
| 4 | **优化器换 Adam** | 现状是手写 SGD（`p.add_(-lr*p.grad)`）+ 梯度 clamp ±1.0，无动量无自适应；GRPO/PPO 实践标准是 Adam |
| 5 | **L 头必须接编码器** | 不再是可选项——联合链前提是两头共享表示；否则"联合"只是名义上的，梯度各走各的 |

✅ **2026-10-03 已实现（Task 7）**：五条约定全部落在 `algo/group_rel.py`——`roll_chain`（一条链
= 一次 episode 的全部 S/L 决策，同一 episode、同一快照源）、`chain_logp`（Σ 求和、带梯度重算）、
`joint_chain_step`（J=1、组内 z、Adam、`epochs=1` 纯组内 REINFORCE 为默认路径）。
两条守卫：`epochs>1` 必须配 `clip_eps`（否则纯浪费）且发**链级尺度**警告；`layout_seed ≠ 0`
直接报错（奖励权重与**特征归一化的 `m_ref`** 会静默错位；⑧ 交期已外生，不是这条守卫的理由）。

> 🔻 **"L 序列预演流"这条已知近似**（2026-10-03 已不适用）：现行实现在**任务生成点同步调
> `policy_l(snap, ...)`**（`des.run_gated`，单线程 SimPy 无并发，见 §5.3.2 的同一机制），
> 链上的每个 L 决策记的是**当时**的活状态快照——不需要预知任务流，也没有"近似形状"。

- ⚠️ **删分批 / 删几何对每步耗时影响很小——省不了时间**

## 10. 风险与定位

### 10.1 最大风险：**没有"一个能被指认为己有的机制"**

文献界标（16 篇有明确贡献声明的论文，每篇都有一个"说得出口的东西"）：

| 论文 | 它的那一个东西 |
|---|---|
| TAAGNet (ESWA) | 队列顺序编码成有向类型边 |
| DTDRL-DS (RCIM) | 多评论家加权优势 |
| HCHGNN-PPO (ESWA) | hub-centric 异构图 |
| GFJSPT-MMRS (SWEVO) | 五部件能耗模型 + 双转速 |
| AEI 103216 (李新宇组) | 物流任务释放时刻 |

**注意**：卡片判定 TAAGNet 三条"**都是表征层/工程层创新**"——说明**这个圈子的门槛不在机制有多深，而在有没有一个机制**。

**我们的账面**：10 约束的**建模广度** + 真 AGV 派车 DES + 引证能耗模型 + τ 校准。
**"有"的三项全是"做扎实"型，没有一项是"新"型。** → **A 单独投二区，临界偏不够。**

### 10.2 出路：从 A 的消融里挖机制

**❌ 曾经的候选已失效（2026-10-02）**：原先观察到"车队规模—吞吐非单调（加 AGV 反而更慢）"，
并归因于区段争用。**换网格后该现象消失**——实测 `n_agv` 3→4→6→8 的 makespan 差异全落在 1–2 个 sd 内，
且同期拥堵恒为 0.01%（§3.3.1）。**原归因（区段争用）不成立，候选作废。**

**另外两个仍待挖的来源**：

1. **约束间的耦合发现**——"加约束 X 会让约束 Y 的收益反转"
2. **消融里的反直觉结果**——某组约束加上去反而更差

**行动**：跑 §6.2 时**专门记录非加性效应**，不是只跑数字。**P4 结束时必须回答"有没有机制"**（§11 门禁）。
