## 0. 一句话

**顶层每 ΔT 选一组规则（PA / LA / RA 各一条）；下层在规则的框架内，逐决策点输出该规则的超参数。**

## 1. 架构

```
实例 + 布局
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Transformer 编码器（共享 —— 与 v2 相同，不改）             │
│   token = 机台 M · 作业 B · AGV V · 全局 G                 │
└────────┬──────────────────────────────┬──────────────────┘
         │ 全局池化                      │ 逐段硬掩码
         ▼                              │
┌──────────────────────────────────┐    │
│ 【顶层】MA —— 三个**独立分类头**   │    │
│   Head_PA → PA 的规则（12 路）     │    │
│   Head_LA → LA 的规则（3 路）      │    │
│   Head_RA → RA 的规则（N 路）      │    │
│   时机：定时器 ΔT / 机障③ / AGV故障⑨ │  │
└──────────┬───────────────────────┘    │
           │ **硬路由**（不是偏置）       │
           ▼                            ▼
┌──────────────────────────────────────────────────────────┐
│ 下层三个头（**连续输出超参数**）                           │
│  PA：ctx = [Z 的 M∪B 段池化] → 走「上层选中的那两个 head」 │
│  LA：ctx = [Z 的 V 段池化 ‖ la_ctx] → 走「选中的那个 head」│
│  RA：ctx = [Z 的 M 段池化] → 走「选中的那个 head」         │
└──────────────────────────────────────────────────────────┘
```

**⚠️ v2 的三个 `B` 矩阵（`B_PA`/`B_LA`/`B_M`）全部删除。**

## 2. 四个 agent 的规格

| Agent | 管什么 | 触发 | **动作** | 受 MA 影响吗 |
|---|---|---|---|---|
| **MA**（顶层） | 定规则 | 定时器 ΔT / 扰动 | **3 个分类**（12 / 3 / N） | —— |
| **PA**（生产） | 机台 | 每决策点 | **4 个 `λ` 连续** | ✅ 硬路由 |
| **LA**（物流） | AGV 派车 | 与 PA 同一点 | **待定**（§4.4） | ✅ 硬路由 |
| **RA**（资源） | 机台生命周期 | 完工且下一件未上机 | **`A` 连续** | ✅ 硬路由 |

## 3. 传输机制：**硬路由**（每条规则一个 head）

**顶层选定规则号 ⟹ 直接选对应的那个 head。没有 one-hot、没有偏置。**

```
上层选定 (job_rule = k, machine_rule = m)
   │
   ▼
ctx = z[:, 该段].mean(dim=1)          # (B, 128) 段内池化
u_j = Head_job[k](ctx)                # (B, 2) —— 只走 k 那个 head
u_m = Head_mach[m](ctx)               # (B, 2) —— 只走 m 那个 head
param = lo + (hi − lo) · sigmoid(u)   # 映到 [0, 1]
```

**head 数**：PA = 4 个作业 head + 3 个机台 head（见 §4.6）。LA / RA 同理。

**⚠️ 为什么不用 one-hot 拼输入**（= Shi et al., AEI 65:103195 (2025) 的 `f32` 那种做法）

| | one-hot 拼输入 | **硬路由（v3）** |
|---|---|---|
| 未选的规则 | **仍进计算**（只是权重可能小） | **根本不进计算** |
| 下层能否"忽略"上层 | ⚠️ 可能（学到把 one-hot 的权重压小） | **不能** |
| head 数 | 1 个共享 | 每条规则一个 |

**⟹ 硬路由从结构上保证上层不可被绕过。**

**⚠️ 为什么不硬掩码**：下层输出的是**参数**，没有"规则 logits"可掩。**硬路由就是掩码的等价物。**

**⚠️ 相对 v2 的 `+ B·g`**

| | v2：`+ B·g` | **v3：硬路由** |
|---|---|---|
| `B` 初值 | **零** | —— **没有 `B`** |
| 第 0 步的敏感度 | **恒为零**（`g @ 0 = 0`） | **非零**（选不同 head ⟹ 走不同权重） |
| 后果 | `σ_G = 0` ⟹ MA 全程无梯度（**§124 实测 `loss_A` 200 步全 0**） | **MA 从第 0 步就有梯度** |

**⚠️ 硬路由的代价（登记，见 §10）**：每个 head **只在上层选它时才收到梯度**
⟹ 少被选的 head 可能学不好（专家网络的不均衡问题）。**v3 未处理。**

## 4. 超参数设计

### 4.0 ⚠️ 三条硬约束（决定"能不能加"与"加几个"）

**① 单调变换无效。**
`apply_pa_rule` / `la_rule_policy` 都取 `argmin`。而 `x^α`（α>0）**严格单调** ⟹
**`argmin` 不变** ⟹ **幂指数是装饰**（实测：5 个 α 值给同一个 `argmin`）。
**⟹ 超参数必须让两个量进比较，不能只做单变量变换。**

**② `λ` 必须有界。**
`X + λ(Y₁+Y₂)` 当 `λ→∞` 时退化成 `λ·(Y₁+Y₂)` —— **`X` 的系数被压成 0**，
各规则的族**塌成同一个**。**⟹ `λ ∈ [0, 1]`。**

**③ 各规则"漏掉"的量不能相同。**
若所有规则混同一组辅量，它们就都成了同一个流形的不同参数化 ⟹ **上层选规则变多余**。
**⟹ 每条规则固定自己的 `X`（系数恒为 1），且各漏掉一个不同的量。**

### 4.1 统一单位

**所有打分项换算成「相对 `now` 的分钟」。** 这是"三项能相加"的前提。

| 原始量 | 换算 |
|---|---|
| **时刻** `t` | `t − now`（分钟） |
| **无量纲**（利用率等） | `· M_ref`（分钟）—— `M_ref` 是现成的参考调度 makespan |
| **时长** | 原样 |

### 4.2 PA · 作业侧（4 条，每条 **2 个**超参数）

| 规则 | `X`（系数恒 1） | `λ₁ · Y₁` | `λ₂ · Y₂` | **漏掉的** |
|---|---|---|---|---|
| **SPT** | `APT` | `wait` | `due_margin` | **`RTJ`** |
| **SRPT** | `RTJ` | `wait` | `due_margin` | **`APT`** |
| **EDD** | `due_margin` | `RTJ` | `wait` | **`APT`** |
| **EAJ** | `ready_delay` | `APT` | `due_margin` | **`wait`** |

`λ₁, λ₂ ∈ [0, 1]`。**`λ = 0` ⟹ 逐位退化成原规则。**

⚠️ `EDD` 原来用 `due`（**时刻**）⟹ 这里必须改成 `due_margin = due − now`（**时长**），
否则与 `RTJ` 不同单位、不能相加。**这会让 EDD 的行为与 v2 不同**（原 `due` 与 `due_margin`
只差一个常数 `now`，`argmin` 相同；但与辅量混合后不再相同）。

### 4.3 PA · 机台侧（3 条，每条 **1 个**超参数）

**⚠️ 为什么只有 1 个（不是 2 个）**：机台侧**唯一的无量纲量是 `util`**，
它跟另两个（`pt` / `avail_delay`，都是分钟）**不能直接相加**。
要混就得引外部尺度（`M_ref` 之类）——**为省一个参数引新依赖不值**。
**故机台侧每条只混**同分母**的那一项：**

| 规则 | `X` | `λ · Y` | 两项的单位 |
|---|---|---|---|
| **SMPT** | `pt` | `λ · avail_delay` | 分钟 / 分钟 ✓ |
| **MINU** | `util` | `λ · (pt / den)` | 无量纲 / 无量纲 ✓ |
| **EAM** | `avail_delay` | `λ · pt` | 分钟 / 分钟 ✓ |

`den = minu_denominator(view, m) = max(avail_at, MINU_TIME_FLOOR)`（**现成的**，`MINU` 的分母）。

**⚠️ `MINU` 混 `pt / den` 的语义**："利用率低的里面，挑**这活占它多久比例小**的" ✓

**⟹ PA 的总参数数 = 4 作业 × 2 + 3 机台 × 1 = `11`。**

### 4.4 LA（3 条，每条 **1 个**超参数）

**⚠️ 与 §4.2/§4.3 同样的问题**：LA 的三个量单位不齐（`cost` 分钟 · `util` 无量纲 · `arrive` 时刻）。
**故三条都各混**同单位**的一项，且 `LATEST_IN_TIME` 的**两级结构保留**（只在第二级混）：**

| 规则 | 打分 | 两项的单位 |
|---|---|---|
| **MINCOST** | `cost + λ · arrive_delay` | 分钟 / 分钟 ✓ |
| **MINU** | `util + λ · (cost / den)` | 无量纲 / 无量纲 ✓ |
| **LATEST_IN_TIME** | 第一级不变；第二级 `±arrive + λ · cost` | 分钟 / 分钟 ✓ |

`den = max(free_at, MINU_TIME_FLOOR)`（**现成的**）·
`arrive_delay = max(0, arrive − ready_at)`（**还要等多久才赶得上**）。

**⚠️ `LATEST_IN_TIME` 的两级结构** —— 第一级是"0 = 赶得上 / 1 = 赶不上"的**硬分类**，
**参数不动它**（否则"赶得上"的语义会随参数漂）；**只在第二级按 `cost` 加权**。

### 4.5 RA（3 条，每条 **1 个**）

| 规则 | 判据 | 超参数 |
|---|---|---|
| **1 役龄阈值** | `役龄 ≥ A` 就保养 | `A` |
| **2 空闲窗口** | 只在"完工且下一件未上机"时保养，且 `役龄 ≥ A` | `A` |
| **3 负荷优先** | 在 `役龄 ≥ A` 的机台里，挑积压最多的先保养 | `A` |

`A ∈ (0, 1]`，乘 `pm_interval` 得**实际阈值**。

⚠️ **规则 2 就是 v2 的实现**（"触发 = 机台完工且下一件未上机"）。**保留它作为一个 option。**

### 4.6 多 head + **硬路由**

**每条规则一个 head，输出它自己的那几个参数。**

| | |
|---|---|
| **PA** | **4 个作业 head**（各 2 个参数）+ **3 个机台 head**（各 2 个参数） |
| **上层选** | `(job_rule, machine_rule) ∈ 12` |
| **只激活** | **被选中的那两个 head** |
| **PA 的动作** | `(λ_job₁, λ_job₂, λ_mach₁, λ_mach₂)` —— **4 个连续量** |

**⚠️ 这比"共享头 + one-hot"更硬**：没被选的 head **根本不参与计算**
⟹ **上层不可替代**（下层无法"学会忽略" one-hot）。

**⚠️ 阶段 B 的梯度只落在被选中的 head 上** —— 只有它们产生了动作。

## 6. 训练 —— 沿用 v2 的交替，只换动作空间

```
for 每个顶层决策点 t:
  ── 阶段 A ──  （更新 MA，下层冻结）
    1. 采 G 组 (rule_PA, rule_LA, rule_RA)
    2. 每组：下层用 **确定性参数 μ**（连续策略的确定性模式）跑 ΔT → R
    3. Â_macro = (R − μ_G)/(σ_G + ε)
    4. 只更新 MA 的三个分类头
  ── 阶段 B ──  （更新下层，规则冻结）
    5. (rule*) = argmax R
    6. 采 M 条轨迹，条件在固定 rule* 上（stop-gradient）
    7. Â_micro = (R − μ_M)/(σ_M + ε)
    8. 只更新 PA / LA / RA 的参数头
```

### 6.0 ⭐ 为什么 v3 仍然需要交替（而理由比 v2 更强）

**① 成本 —— 这条与 v2/v3 无关，是硬的。**

| 组 | 更新 | 成本（`G = M = 8`） |
|---|---|---|
| **分层组** | **交替** | **16T** |
| 分层组 | 同步 | **64T** ❌ |

**⟹ 「要分层组就必须交替」（`docs/v2/design.md` §12.0）。**

**② 非稳态 —— v3 里**更强**。**

v2 的下层改的是"选哪条规则"；**v3 的下层改的是"那条规则的**参数**"，
直接改变那条规则的**实际行为**。**
⟹ 上层对"选这个规则好不好"的评估，**过时得更快**。

**③ 而 v2 的病，v3 正好治了。**

v2 的交替**名义上在跑，实际阶段 A 全程空转**：
`B` 零初始化 ⟹ G 条分支逐位相同 ⟹ `σ_G = 0` ⟹ `loss_A` 200 步全 0（`docs/v2/progress-log.md` §124 实测）。

**v3**：选不同规则 ⟹ **走不同的 head** ⟹ **行为结构不同** ⟹ **`σ_G > 0` 从第 0 步就成立。**
**⟹ 交替在 v3 里第一次真正起作用。**

**⚠️ 而两个 v2 的补丁 v3 不需要了**：`lr_B`（没有 `B` 了）· `B` 零初始化的取舍（`docs/v2/design.md` §95）。

### 6.1 连续动作的口径（**要写死**）

| | |
|---|---|
| **动作** | **`u ∈ R`（无界）** |
| **参数** | `param = lo + (hi−lo)·sigmoid(u)` |
| **`logp`** | **在 `u` 上算**：`log N(u; μ(s), σ)` —— **不需要 Jacobian 修正** |
| **σ** | **固定，不学。起步 0.5，待扫** |
| **阶段 A 的确定性模式** | **取 `μ`（不是采样）** |

**⚠️ 为什么 `σ` 固定**：σ 的唯一作用是探索；而**"策略塌缩"正是 v2 这一整轮在治的病**
（`docs/v2/progress-log.md` §146）。**学 σ 等于再开一个塌缩面。**

**⚠️ 为什么动作定义在 `u` 上**：`u` 才是被采样的量；`param` 是它的确定性函数。
在 `u` 上算 `logp` ⟹ **策略梯度正确且不需要 Jacobian。**

## 9. ⭐ 动机：四条经典里，哪几条现在成立

**逐条核过 FuN（arXiv:1703.01161）与 HIRO（arXiv:1810.01257）原文。**

| # | 经典动机 | **v2** | **v3** |
|---|---|---|---|
| **①** | 长时程信用分配 | ❌ 不成立（episode 短、奖励密） | ❌ **不成立** |
| **②** | **时间抽象** | ⚠️ 勉强（`g` 持续但下层照变） | **✅ 成立** —— 规则 = option，ΔT 内固定，下层在框架内调参 |
| **③** | **探索** | ⚠️ 动作空间小 | **✅ 成立** —— 上层在规则空间探索，下层在参数空间探索 |
| **④** | 稀疏奖励 | ❌ 不成立 | ❌ **不成立** |

**⚠️ 两条成立、两条不成立。成立的这两条是**从设计里长出来的**，不是补上去的。**

### 9.1 v2 为什么被否

**四条经典动机**一条都不成立**（①④ 明确不成立，②③ 勉强）。**
**⟹ v2 的分层是"借了形式，没接上动机"。** 用户在 2026-10-10 的追问里指出这一点，
**判定成立**（见 `docs/v2/progress-log.md`）。

### 9.2 与 Shi et al., AEI 65:103195 (2025) 的关系 —— ⚠️ **要小心**

| | **Shi 2025** | **v3** |
|---|---|---|
| 上层输出 | **目标**（MS / TC，2 选 1） | **规则**（12 / 3 / N 选 1） |
| 下层输出 | **规则**（27 条 CDR） | **规则的超参数** |
| 传输 | `f30–f32` 拼进 PA/LA 的特征 | **硬路由**（选 head）—— **这一点**不同**（§3） |
| 上层实质作用 | **切换奖励函数**（式 50 ↔ 式 52） | **决定下层动作空间的基函数** |
| 触发 | **每个决策点** | **每 ΔT + 扰动** |

**⚠️ 传输机制相同（都是"拼进输入特征"）—— 拼接是通用做法，不算同构。**
**⚠️ 但"上层选东西、下层照着做"这个骨架，两家都有。论文里必须逐项对照，不能装看不见。**

### 9.3 🔴 **仍然没解决的一条：上下层优化同一个 `R`**

**FuN**：Worker 用 `R + α·R^I`（**内在奖励**）；两层**不传梯度**。
**HIRO**：下层用 `−D(f(s'), g)`（**纯目标奖励**，不是任务奖励）。
**v3**：**两层共用同一个 `R`。**

**⟹ 这一条 v3 没改。** 它是"分层有没有独立动机"的最后一个缺口。
**候选修法**（未裁定）：给下层加一项"参数是否被上层选中"的辅助信号，或让阶段 A 用更粗的时间尺度。
**在它解决之前，v3 的分层动机是"两条成立的经典动机"，不是"上下层各司其职"。**

### 13.3 ⚠️ 三处**最容易做错**的地方

**① `logp` 算在哪个变量上。**
动作是 `u`（无界），`param = lo + (hi−lo)·sigmoid(u)` 是它的确定性函数。
**`logp` 必须算在 `u` 上** —— 算在 `param` 上会漏掉 Jacobian，**策略梯度就错了**。

**② 阶段 A 的"确定性模式"。**
离散时是 `argmax`；**连续时是取 `μ`**（不是采样）。
**搞错的话 `σ_G` 会混进下层自己的采样噪声**，MA 的优势就不再是"规则好不好"。

**③ 上层选的规则号 ↔ 下层用的 head 要**对得上**。**
PA 的规则号决定走**哪一对**（作业 head + 机台 head）；**不能**错位到 LA/RA 的 head。
⚠️ 规则号 = `PA_RULE_NAMES` 的下标，**作业 = `idx // 3`、机台 = `idx % 3`**（
与 `apply_pa_rule` 的拆法**逐字同源**）—— 两处各写一遍就必然会漂。
