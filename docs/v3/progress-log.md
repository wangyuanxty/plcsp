## §1 ⭐ v3 开线（2026-10-10）

### 1.1 起因：用户连续追问，把 v2 的立论基础问穿了

| # | 用户的话 | 查证结果 |
|---|---|---|
| 1 | 「encoder 的输出向量直接就输入到下层 agent，那上层很可能根本不起作用啊」 | **在**表示能力**上成立** —— 下层看得到全部 `Z_t`，`g` 是它的一个函数 |
| 2 | 「shi2025 OA 那不就是对偏好做了个翻译再给下层？下层直接读偏好不就行了」 | **对他们不成立**（OA 切的是**奖励函数**，下层不知道自己在被哪个奖励评价）；**对我们成立** |
| 3 | 「分层 RL 的目的是什么？」 | 四条经典动机，**v2 一条都不成立**（见 `docs/v3/design.md` §9） |
| 4 | 「必须改，不然分层没有动机不是硬套吗？」 | **判定成立** |
| 5 | 「你这就相当于 shi2025 了」（否掉助手的"goal-reaching 奖励"提案） | **成立** —— 那就是"上层调制下层奖励"，与 Shi 2025 同构；且违反 `docs/v2/design.md` §8.2「不能写复现其框架」 |
| 6 | 「让上层 agent 输出规则，下层 agent 输出这个规则的超参数」 | **采纳** —— 见 §1.3 |

### 1.2 ⭐ 核过的文献（**全部读原文，不是记忆**）

| 文献 | 核出的关键事实 |
|---|---|
| **FuN**（Vezhnevets et al., ICML 2017, **arXiv:1703.01161**） | ① Worker 用 `R + α·R^I`（**内在奖励**）② **两层不传梯度**，且**明确拒绝**端到端（"would deprive Manager's goals g of any semantic meaning"）③ **`φ` 特意不带偏置，以保证 goal 永远影响策略** —— **与 v2 的 `B` 零初始化直接对立** |
| **HIRO**（Nachum et al., NeurIPS 2018, **arXiv:1810.01257**） | ① 下层奖励是 `−D(f(s'), g)`（**纯目标**，不是任务奖励）② 批评端到端学表示"**欠定义**——不是所有子任务都能在这个空间里表达" |
| **Shi et al., AEI 65:103195 (2025)** | ① OA 只有 **2 个动作**（选 MS / 选 TC）② 它的实质作用是**切换奖励函数**（式 50 ↔ 式 52）③ `f30/f31`（偏好）**同时进特征和奖励** ④ **每个决策点都触发**，**不是时间抽象** ⑤ 消融只有 **N-OA**，而且**同时改了奖励**（不干净）⑥ **从没跑过"扁平 vs 分层"** |

**⚠️ 助手此前关于 FuN 的两条说法是错的**（"逐元素相乘"、"任务奖励 + 方向损失"），**已在核原文后更正。**

### 1.3 v3 定下的架构（详见 `docs/v3/design.md`）

```
MA（每 ΔT，三个独立分类头）
   Head_PA → PA 的规则（12 路）
   Head_LA → LA 的规则（3 路）
   Head_RA → RA 的规则（3 路）
        │  **硬路由**：按规则号**选对应的 head**（不是偏置、不是 one-hot）
        ▼
PA → 4 个 λ 连续     LA → 3 个 λ/slack     RA → A 连续
```

**删掉 v2 的三个 `B` 矩阵。**

**⚠️ 2026-10-10 当日更正两处**（设计文档 §3/§4 已改准，此处同步）：

| 原提案 | 为什么不行 | 改成 |
|---|---|---|
| 每条规则一个**幂指数** `x^α` | **`argmin` 对单调变换不变** ⟹ 幂指数是装饰（实测：5 个 α 给同一个 `argmin`） | **混合** `X + λ₁Y₁ + λ₂Y₂` |
| **one-hot 拼进下层输入** | 未选的规则仍进计算 ⟹ 下层可能学会忽略它 | **硬路由** —— 没被选的 head **根本不进计算** |

**而「每条规则不要趋同」这条推出了三条硬约束**（详见设计 §4.0）：
① 单调变换无效 ② `λ ∈ [0,1]` 有界（否则各族塌缩）③ 各规则漏掉的量不能相同。

**两条经典动机因此成立：**
- **② 时间抽象** —— 规则 = option，ΔT 内固定
- **③ 探索** —— 上层在规则空间、下层在参数空间

### 1.4 ⚠️ 仍然没解决的一条

**上下层优化的是同一个 `R`。** FuN 有内在奖励、HIRO 有纯目标奖励，**v3 没改这一条**。
**⟹ 在它解决之前，v3 的分层动机是"两条成立的经典动机"，不是"上下层各司其职"。**

### 1.5 未定（详见 `docs/v3/design.md` §10）

`σ` 取值 · RA 规则条数 · `(lo, hi)` 界 · MA 三头是否联合 · **代码放哪** · 奖励口径欠账

### 2.3 ⭐⭐ 三条结论

**① 两个口径最终都输给最佳规则**（输 23.4% / 16.2%）。

**② 换口径**没有**治塌缩 —— 只改变落在哪个不动点。**
```
ref    s1: 107 106  81  67  67  91 114  91  91    ← 到处跳
minmax s1: 107  81  85  85  85  85  85  85  85    ← 从 step 25 起卡死在 85
```
**两条曲线都只取少数几个值** ⟹ **都还是塌缩。**

**③ 「学到又丢掉」两个口径都有** —— `ref` 摸到过 **67.37**（赢规则 11.8%），最后停在 90.80。

**⚠️ 而 `minmax` 的峰值**比 `ref` 差** —— 与"新口径更好"的预期相反。
「稳」和「好」在这里是冲突的。**

### 2.4 ⟹ 所以

> **口径不是病根，塌缩才是。**
> **v3 改的是动作空间的结构（离散 → 连续），那才可能治到根上。**

**⚠️ 而这仍是**推测** —— 连续动作空间也可能塌（σ 塌到 0 那条路，v3 用固定 σ 堵）。

**5 条新测试**（`test_pa_rules.py` §9）：

| # | 钉住什么 |
|---|---|
| ① | `λ = 0` 与原规则**选中同一个工件**（**在测试里独立重写原式**比对，不与实现共用代码） |
| ② | `λ` 越界**显式报错**（不静默夹取） |

### 4.3 ⚠️ 一处实现细节值得记

**`λ = 0` 走快路返回原实现**，不走统一公式。理由：

- `EDD` 的原量 `due` 可能是 `INF`；统一公式里 `0 × inf = nan`
- `EAJ` 的原量是**时刻**，v3 的主量是**时长** —— 数值差一个 `now`，但 `argmin` 相同

**⟹ 快路同时保住了「逐位不变」和「公式统一」两件事。**

## §5 ✅ 步 2：RA 加 3 条保养规则（2026-10-10）

### 5.1 做了什么

`plcsp_v3/hrl/rules.py` 加：

| 加了什么 | |
|---|---|
| `PM_RULE_NAMES = ("AGE", "QUEUE_EMPTY", "OLDEST")` · `N_PM_RULES = 3` | 规则表 |
| `_resolve_pm_rule(rule)` | 下标↔名字，非法值**显式报错** |
| `pm_rule_policy(rule, threshold_min)` | → **`policy_m` 回调** |

**规则（在触发点、且**未逾期**时判）：**

| 规则 | 判据 |
|---|---|
| **`AGE`** | `役龄 ≥ threshold` |
| **`QUEUE_EMPTY`** | 同 `AGE`，**且**输入队列空（现在停机不堵活） |
| **`OLDEST`** | 同 `AGE`，**且**本机役龄**不小于**其它任何机台（一次只保最旧的） |

**⚠️ 三条规则的超参数是**同一个阈值**（设计 §4.5）—— 区别在**额外判据**，不在参数。**

### 5.2 ⚠️ 两处设计上的注意（都已如实写进 docstring）

**① 触发点是**给定的**，规则不改它。**
`des.MachineSim._pm_after_op`（工序完工、下一件未上机）是"要停机才能保养"的**唯一窗口**。
规则只决定"在那个窗口里保不保"。**放同一时点，使"规则 → 策略"只改**谁决定**，不改时点语义。**

**② 逾期是硬底线 ⟹ 规则只能提前，不能推迟。**
`pm_clock >= pm_interval` 时**直接强制、不调用回调** ⟹
**`threshold >= pm_interval`（即 `A = 1`）时规则恒不主动**（退化成只靠强制）。

**⚠️ 规则层不认识 `pm_interval`** —— 参数取**绝对值**，比例 `A → threshold` 的换算由调用方做
（`threshold = A · cfg.pm_interval`）。这样规则层只依赖 `Snapshot`，不依赖 `SimConfig`。

## §6 ✅ 步 3：两个新头模块（上层三分类 / 下层每规则一 head）（2026-10-10）

### 6.1 ⚠️ 本步**只加模块，不动 `PolicyOut`**

**理由**：`PolicyOut` 是「换头」与「换采样」的**接缝** —— 改它会让
`rollout.py` / `train.py` **同时编译不过**。**留到步 4 与"换采样"一起改。**

**⟹ 步 3 的验收是模块级的**（前向通 + 断言），不是端到端的。

### 6.2 加了什么

`plcsp_v3/hrl/agents.py`（**233 → 317 CRLF**）：

| 模块 | 干什么 |
|---|---|
| **`RuleSelectHeads`** | **上层（MA）**：全局池化 → **三个独立**分类头（`{"PA": 12, "LA": 3, "RA": 3}`） |
| **`RuleParamHeads`** | **下层**：**每条规则一个 head** → 它自己的**连续**参数（μ）。**硬路由** |

**⚠️ `RuleSelectHeads` 的三个头是**独立**的** —— 与 v2 的 `MAHead`（3 个 4 档分档）**同构**，
只是类数从 `4` 变成 `12 / 3 / 3`。**v2 那条注释仍然成立**：
「顶层是 3 个**独立**的分档，不是一个 64 路的类别」。

**⚠️ `RuleParamHeads` 的输出是 μ（无界的动作 `u`），不是参数本身。**

（设计 §4.2 / §4.4 / §4.5）。

### 10.2 🔴 真 bug（一）：**参数与规则错位** —— 最隐蔽的一类

**症状**：`flat_rollout` 连调两次读数不同；两臂比链、并行 vs 顺序比链全不对（三个测试同时红）。

**根因**：`NetPolicy._forward` **没传 `rules`**。
`HierarchicalPolicy.forward(rules=None)` 于是按 **`rule_logits.argmax()`** 去路由 `param_mu`
（决定走哪个参数 head）。**而本类里规则是 `policy_ma` 用 `self.gen` 采的**（`self.cur`），
两者**一般不同** ⟹ `apply_pa_rule(self.cur["PA"], …, lam)` 用的是**采样的**规则，
而 `lam` 却来自**另一条规则**的 head。**这正是设计 §13.3 ③ 点名的那件事。**

**⚠️ 为什么极难发现 —— 两个天然盲区：**

| 盲区 | 为什么 |
|---|---|
| **`greedy=True`** | 那时 `policy_ma` 走 argmax ⟹ `self.cur` **恰好就是** argmax ⟹ 两条路一致 |
| **"同 seed 复现"** | 错位是**确定性**的 ⟹ 两次错到同一处 ⟹ 仍然"可复现" |

**⟹ 当时那 146 条测试里，没有一条能抓到它。**

**✅ 修法**：`_forward` 传 `rules=self._cur_rules()`（冻结路由）。
**✅ 并补一条能抓它的测试**：`test_param_mu_is_routed_by_the_rules_in_force_not_by_argmax`
—— 冻结一组**非 argmax** 的规则，拿两组规则各重算一遍 `μ`，逐位比。
**已**验证它有效**：把 `rules=` 去掉 ⟹ **该条精确报红**，其余 145 条仍绿。

**⚠️ 副作用（是好的）**：传了 `rules` ⟹ `forward` 不再走
`torch.distributions.Categorical(logits).sample()` —— 那条路用的是**全局** torch RNG，
**不受 `self.gen` 控制**，每次前向都推进全局随机流。**那是症状，路由才是根因。**

**⚠️ v2 有没有它？** v2 的 `agents.py:210-211` 有**同样的** `Categorical(...).sample()`，
但 v2 丢弃它的返回值（`policy_ma` 用 `out.g_logits` 重采）⟹ **无可观测后果**。
**v3 不一样**：那个 `sel` 直接决定 `param_mu` 走哪个 head ⟹ **有后果**。

### 10.3 ⚠️ 真 bug（二）：v3 换头时**丢了**一条护栏

**v2 的 `_MaskedScoreHead.forward` 有一条"空掩码段显式报错"。v3 改用段内 `mean` 之后丢了它。**
而 `mean` 对**空**切片给的是 `nan`，**不报错** ⟹ "这个 agent 没接上"会变成**无声的坏策略**。

**✅ 已补**：`HierarchicalPolicy._pool(z, rng, name)`，`hi <= lo` 时显式报错。

### 10.4 🔴 新的开放线索：阶段 B 的 `σ_M` 可能为 0

**v3 的下层是连续参数**，微小的 `λ` 差异**可能不改变 `argmin`** ⟹ 两条分支逐位跑出同一条链
⟹ `σ_M = 0` ⟹ `Â ≡ 0` ⟹ **阶段 B 空转**。
（v2 的下层是"12 条规则选 1"，两条采样撞上只需 ~1/12 的概率，所以这个病在 v2 里轻。）

**实测**（MK01 · 随机初始化 · `dt_events=50` · seed 0 · **4 个顶层点**）：

| `M` | 各顶层点的 `σ_M` | 非零 |
|---|---|---|
| **2** | `[0, 0, 0, 0]` | **0 / 4** |
| **4** | `[0, 1.850, 0, 0]` | 1 / 4 |

## §11 ✅ 顺序裁定：`train.py` 改成 **A 先 B 后**（与设计 §6 一致）（2026-10-10）

### 11.1 改了什么

`hrl/train.py` 的 `train_step`：

```python
# 改前
for name, fn, kw in (("B", phase_b, {"M": M}), ("A", phase_a, {"G": G})):
# 改后
for name, fn, kw in (("A", phase_a, {"G": G}), ("B", phase_b, {"M": M})):
```

模块 docstring 与 `train_step` 的 docstring 同步改。

### 11.2 为什么可以改

**v2 反着来（B 先 A 后）的唯一理由**：三个 `B` 矩阵**零初始化** ⟹ 起始时 `g` 不影响行为
⟹ 阶段 A 的 G 条段逐位相同 ⟹ `σ_G = 0` ⟹ **顶层拿不到梯度**
（`docs/v2/progress-log.md` §124 实测 200 步全 0）。

**⚠️ v3 里那条理由不存在**：选不同规则 ⟹ **走不同的 head** ⟹ 行为结构不同 ⟹
`σ_G > 0` **从第 0 步起就成立**（设计 §6.0 ③ / §8）⟹ **不必再让 B 打头阵。**

### 11.3 读数（`M=4, G=2, dt_events=50`, MK01, 10 步 **49.0 s**）

| | 顺序 **B→A**（§10.6 那次，`M=2`） | 顺序 **A→B**（本步） |
|---|---|---|
| 第 0 步 A 的 `gn_upper` | `1.367e+01`（跑在 B 更新**之后**） | **`1.31e+01`（跑在初始 net 上）** |
| 10 步 A 的 `gn_upper` 范围 | 10 ~ 16 | **11.5 ~ 18.4** |
| 10 步 B 的 `gn_lower` 范围 | 0（第 0 步）~ 1.0e+03 | **173 ~ 398** |

**⚠️ 两次的 `M` 不同（2 vs 4）⟹ 不能逐格比。** 可比的是那条结论：
**A 从第 0 步起就有非零梯度** —— 改顺序后这一点**更强**（那时 net 还没被 B 动过）。

## §12 ⭐ 量了阶段 B 的 `σ_M`：**参数在探索，只是没跨过 `argmin`**（2026-10-10）

### 12.1 口径

按 `docs/v3/experiment-plan.md` §2：MK01 · `pm_interval=30` · `target_failures=4` ·
`finite_buffer=True` · **`layout_seed=0`** · `dt_events=20` · `M=8` · seed 0 ·
**未训练的 net**。⟹ **n_top = 14**。扫 `σ ∈ {0.5, 1.0, 2.0}`。

### 12.2 读数

| `σ` | `σ_M > 0` 的顶层点 | 段内**有完工**的 | **有完工但"链全同"** |
|---|---|---|---|
| **0.5** | **4 / 14** | 11 / 14 | **0** |
| **1.0** | **8 / 14** | 11 / 14 | **0** |
| **2.0** | **8 / 14** | 11 / 14 | **0** |

**⚠️ 最后一列恒为 0 ⟹ §10.4 的成因猜错了。**

### 12.3 ⭐ 结论：**参数真的在探索，不动的是 `argmin`**

**M = 8 条分支，每一个顶层点都是 `种链 = 8/8`** —— 8 条**互不相同**的参数序列。
⟹ **不是"噪声没接上"，也不是"两条分支撞在一起"。**

**是**：8 组不同的 `λ` **算出了同一个决策序列**（每一步的 `argmin` 都没跨过门槛）
⟹ **段回报逐位相同** ⟹ `σ_M = 0` ⟹ `Â ≡ 0` ⟹ **那个顶层点不产生梯度。**

**⚠️ 这与设计 §4.0 ① 是同一个根**：`λ` 混的是**辅量**，而辅量在很多决策点上**不改排序**。

### 12.4 对训练的含义：**阶段 B 的有效样本量只有一半上下**

| `σ` | 有梯度的顶层点 |
|---|---|
| 0.5 | **4 / 14** |
| 1.0 | **8 / 14** |

**⚠️ 空转的那些**不都是"空段"** —— `j=8`（段内 **10** 道工序完工）与 `j=9`（6 道）
在 `σ=0.5` 下都空转。**那是"重要"的段。**

（"空段"确实有三个：`j=3` / `j=10` / `j=13`，段内 `ops = 0`。**那三个 `σ_M = 0` 是自然的。**）

### 12.5 ⚠️ 更正 §10.4 的成因（数字对、解释要改）

| | §10.4 写的 | **实测** |
|---|---|---|
| 现象 | `σ_M = 0` | ✓ 同 |
| 成因 | "两条分支**逐位跑出同一条链**" | ❌ **否** —— 是"**8 条不同的链给出**相同的段回报**"** |

**⟹ `plcsp_v3/tests/test_train.py` 里那句已改。**
