## 3. 核心现象

**策略最好只能**追平**最好 CDR，从来没赢过。三条路都试过：**

|---|---|---|
| **① MS 单目标** | 只 PA、只优化 MS、单次运行 | 10 个 seed 里 **2 追平、8 输、0 赢** |
| **② 换大实例** | `Exp(16/140)` → `Exp(90/801)` | 规则极差**缩小**（101% → 74%），方向反了 |
| **③ 原文的 HV 口径** | 两目标 + 20 次重复 + Pareto 集 | 策略/CDRs = **0.90×**（**输**）；策略/RN = 1.05× |

#### 4.7.2 错误二：训练实例池的 `seed` 是死的

`env/shi_instances.py` 的 `named(n, jobs, seed=...)` 原实现是「**从 `seed` 起顺序搜，

### 4.17 ⭐⭐ **找到了第一个与比值单调相关的旋钮：`tt` 强度（`layout_scale`）**（2026-10-15）

#### 4.17.1 用户提出的机制

> *"让 MS 和 TC 这两个方向相反 —— CDR 选的规则在 MS 上很好的时候 TC 就很差，
> 这样 RN 不就有机会能在 HV 上赢了吗"*

**机制成立，数学上可验：**

```
HV 的参考点 = (1, 1)；单点 (a,b) 的 HV = (1−a)(1−b)
a + b 固定时 **a = b 处最大** ⟹ 走向两端（分化）⟹ 每个点都缺一角 ⟹ HV 小
```

**实测数例**（与暴力栅格积分逐位一致，见 §4.17.3）：

```
单点 (0.5, 0.5)              HV = 0.2500
两点 (0.1,0.9) + (0.9,0.1)   HV = **0.1700**   ← 分化了，反而**小** ✓
```

### 4.22 ⭐⭐⭐ **S 层探针：「最近」**永远**就是「最早能开工」—— 机台不排队**（2026-10-15）

#### 4.22.1 口径

接管 PA 派工回调，逐决策点记录：`EAJ+SMPT` / `LATEST_IN_TIME` · 场景 `100000` · **124 个决策点**。

**代理量**：`t_k = max(avail_k, now + d_k)`（候选机台 k 的最早可开工时刻）。
`近` = `argmin d`，`自由` = `argmin avail`，`最优` = `argmin t`。

#### 4.22.2 读数

| | `scale 12.5` / 装卸 0 | `scale 5` / 装卸 2.67 |
|---|---|---|
| 决策点 | 124 | 124 |
| 「最近」== 「最早可用」 | **34%** | **40%** |
| 规则实际选中的 == 「最近」 | 35% | 33% |
| **「最近」较「最优」多等** | **中位 0.00 / 均值 0.00** | **中位 0.00 / 均值 0.00** |
| 选「最早可用」较「最近」多走 | 中位 1.75 / 均值 2.43 min | 中位 0.10 / 均值 0.84 min |
| 候选之间的**可用时刻之差** | 中位 10.44 / 均值 35.51 min | 中位 3.44 / 均值 27.19 min |

#### 4.22.3 ⭐ 关键行：`t_近 − t_最优` **恒为 0**

**构造性证明**：`t_k = max(avail_k, now + d_k)`。若 `avail_近 ≤ now + d_近`，则

```
t_近 = now + d_近  ≤  now + d_k  ≤  t_k      （∀k，因 d_近 是最小）
```

**⟹ 「最近的机台」必然**就是**「最早能开工的机台」。**

**⟹ 只要最近的机台在工件到达前空出来，「省运输」就**自动**是「省工期」⟹ 没有权衡可造。**

#### 4.22.4 ⭐⭐ 根因：**机台不排队**

```
124 道工序 ÷ 18 台机 = 每台 ~7 道 × 平均加工 ~6 min ⟹ 每台 ~40 min 工作量
而 MS ≈ 400 min ⟹ **机台利用率 ≈ 10%**
```

**⟹ 这解释了 §4.21.4：TC 最小那条 CDR 为什么 MS 也好** —— 它选的**近**机台本来就**最快能开工**。

#### 4.22.5 ⚠️ 两个结论（一个作废一个指向）

**① §4.20 那条机制**作废**。**
把候选机台拉开之后，`d_近` 变大，但 `avail_近 ≤ now + d_近` **仍成立** ⟹ `t_近` 仍最小 ⟹ **仍无冲突**。
**⟹ 拉开机台间距打不到靶 —— 因为冲突不在机台那一层。**

**② 冲突若存在，在**【车】**那一层。**

### 4.45 ⭐ **隔离实验：LA 学习是 PA 的主要破坏源**（2026-10-18）

## 6. 已修的实现缺陷（一并列出；**修完没变好**）

1. **终局漏尾**：策略在第 `t` 个决策点的奖励，是在**第 `t+1` 次回调时**才写入的 ⟹ **最后一次没有「下一次」** ⟹ 它和它之后的一切都不进回报。
   实测：`Σr = −104.5`，而 `−makespan = −157.3`（差 **52.8 分钟**，占 34%）。已加 `finish()` + 回报求和断言。
2. **`V=0` bootstrap 错**：GAE 里 `v = list(val) + [0.0]` 把截断片段当成**真终止态**。
3. **ε 的 log-prob 与采样分布不一致**：采样走 `b = (1−ε)π + ε/K`，记录的却是 `log π` ⟹ 离策略样本被当成在策略样本。有效权重 `b/π = (1−ε) + ε/(Kπ)`（K=9、ε=0.9、π=0.4 → **0.35**；π=0.03 → **3.43**）。
4. **`γ<1` 时「望远镜求和 = −makespan」不成立**：
   `Σγ^t(C_t−C_{t+1}) = C_0 + (γ−1)Σγ^{t−1}C_t − γ^{T−1}C_T`，`γ=0.99`、123 步时终局项只剩 **29%**。

**把 1–4 全修掉、用 `γ=1 λ=1 ε=0`（即让回报精确等于 `−makespan`）后，K=9 的 4 个 seed：147.6 / 191.2 / 163.3 / 242.7 —— 比修之前**更差**（修前 4 个是 147.6 / 178.7 / 170.8 / 207.9）。**

5. **`Σ_v y_v` 写死成 `n_agv`**（2026-10-16 修，见 §4.34.1）：
   AEI2025 Eq.(2) 的 `Σ_v y_v` 是**激活**的 AGV 数，代码里写成常数 6。
   判据补成 `agv_busy_min[v] > 0`。**`Exp(16/140)` 上 27 条规则全用满 6 台 ⟹ 逐位不变。**

2. **HV 的归一化基准原文没给。** 本仓现取「该实例上**传进来的全部解**（RN + 27 CDR）各自 min–max 到 `[0,1]` + 参考点 `(1,1)`」（`mo_metrics.normalize_minmax`）。
   **⚠️ 原文只给出「HV ≤ 1」这一条约束，反推不出基准** —— 已试过「含策略解」一档（§4.33.4 的 `baseline_test`），推不到 0.264。
3. **策略评测的采样走 torch 全局 RNG**，其状态取决于之前跑过什么 ⟹ **同一 ckpt 两次跑出的 HV 不同**（1588.60 vs 1656.84）。**这是缺陷，未修。**
4. **单点族的留出余量 +1.51% 仍含 1.8% 量级的噪声**，只能说「真实但极小」，不能说「等于 1.51%」。
5. **训练只有 300 步、4 条链、单实例。** 原文是 1000 epochs、回放记忆 32/32/500、minibatch 32、每 epoch 随机生成新实例。
