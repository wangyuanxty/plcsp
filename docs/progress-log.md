**先澄清"分批"实指**（此前文档只写"分批（batching）"，含义从未定死）：本项目实现的是**投放门控**，不是文献里的加工批。证据 `geosched/env/des.py:250`："`batch_cap` = **同时在途作业数上限**（分批门控：B 层决策的载体）"；`des.py:285`："先入 batch_cap 个，每完成一个作业补一个"。B 层动作 = `cap_opts=[None, 2, 1]`（`m3_smoke.py:25`）。
　→ 与文献中的 **lot-streaming（批量拆分流转）** 和 **parallel batch scheduling（同炉同时加工）** **均非同一决策**。

**依据（两条）**：

1. **文献侧：顶刊 PLCSP 基本无"批"**。§11.1 对位表 10 篇中仅 2 篇标"①分批 ✓"（IJPR 63(4) Lot-streaming、EJOR 326(2) parallel batch），且这 2 篇的"批"是**加工批**，与我们的投放门控不同——**用它们支撑"分批有文献基础"属偷换概念**。另：16 篇有明确贡献声明的论文，创新点归为 7 类（新问题变体 / 图表征 / 动作空间 / 多智能体架构 / 奖励设计 / 扰动触发 / 评测基准），**无一类是分批**。李新宇组对 PLCSP 的界定亦只有两件事："the essence of PLCSP is to provide a series of **operation-AGV pairs**"。
2. **实证侧：分批非杠杆且有害**。bug#8 修复前该环节是**死代码、从未被真测**（§二 bug#8a）；修复后诚实测量：cap=None 500–552 / cap=5 483–576 / **cap=2 656–747（显著变差）**；轴判据结论"**B（分批）门控非杠杆**"（§八）；π_B 自学得 `[0.47, 0.33, 0.21]`——**优先 cap=None，策略自己选择不门控**。

### 13.1 通道化多目标（variant A：`m6_opt_a`）❌ **已否决**

- **做法**：4 条奖励通道（makespan / tardy / moves / energy）**各自组内 z 化后等权求和**——与 MO-GRPO（arXiv 2509.22047）/ Multi-GRPO（2512.00743）的 reward-grouping 同构；设计意图 = 方差对齐、防奖励黑客、免手调权重（z 后各通道 N(0,1) → 等权即均匀贡献）。
- **结果**：30 种子 **mean = 386.93**（median 387.44，min 372.29）vs flat **371.05** → **更差（+4.3%）**；训练轨迹中 eval 平台 373–417 震荡，未见收敛到 flat 水平。
- **判定**：**无增益 → 否决**。与"组内相对已把奖励尺度消掉、无需再分通道"的既有结论一致；通道化引入的等权假设在这一域没有收益。
- **处置**：❌ 已否决，**内部存档**，不进论文（与树式分层、共演化同档）。

### 13.2 通道化 + GRPO-λ 时序折扣（variant B：`m6_opt_b`）❌ **已否决**

- **做法**：A 的通道化 + **GRPO-λ 时序折扣**（L 段 logp 按时效加权 w_t = λ^(T−1−t)，近期决策权重高；λ=0.9）——GRPO-λ（2510.00194）/ eligibility traces（2605.05965）同族。

- **判定**：**无增益 → 否决**。时序折扣未改变结论方向，且该口径仍建立在已被否决的通道化奖励上。

`wᵢ = (1/fᵢ^ref)/Σ(1/fⱼ^ref)`。P2（Task 1–8）把**表征 → 联合链 → 训练 → 验收**整条接通；
表征侧要点见 `INDEX.md` §5.8 与 spec §5.3 的「2026-10-03 已实现」标注，本节只记 **A 的实测数字**。

### 18.1 预算裁定（R1）：验收测试必须分钟级，300 步归脚本

| 件 | 预算 | 角色 |

| `plcsp/m13_train_a.py` | 300 步 × G=8（默认） | 正式训练（后台跑、可 `--resume`） |

⚠️ **30 步的断言 3 是"实测够了才保留严格 `<`"**（R1 允许降级为 `trained < rule × 1.1`）：
实测**反超余量足够**（见 18.3），故**未降级**。若换实例/换预算后反超不了，**照实记录，不硬凑**。

**回归门禁**：`plcsp/tests/` **160 项全绿**（P2 前 156 + 本任务 4），独占实测 **280.56 s（4:40）**。
⚠️ 全程并行（后台 300 步训练 + 全量回归）时同一套测试也全绿，但墙钟翻倍到 681 s——**报数一律取

### 18.2 三条断言的实测（MK01、布局 seed 0、默认 `SimConfig`、同进程 `torch.manual_seed(0)`）

**① 编码器输入非零且是活的**（P0 遗留"全零输入"已消失——P2 的头号验收项）：

| 量 | 实测 | 全零 bug 时的值 |
|---|---|---|
| 一条链的决策数 | **100**（S=55 / L=45）| — |
| `|tok|` 求和（每个决策的整张 `(N,F_MAX)`）| min **52.3** / 中位 57.1 / max 59.4 | **0.0** |
| 非零元素数 | min **80** / 200 个格 | 0 |
| `seg` | (6, 10, 3, 1) = (n_m, n_jobs, n_agv, 1) ✓ | — |
| 首末决策的逐位差异 | **72/200 位不同**（最大差 1.577）| 0（恒零当然"相同"）|

首末不同这一条单列，是因为**"非零"可能是常量伪装**：只有特征随仿真状态真正变化，"实时构造"
才算接上了（`build_tok` 读的是当次 `Snapshot`）。

判据本身另有**变异守卫**（`test_zeroed_features_would_be_caught`，本仓惯例）：把 `build_tok`
换回 P0 的**全零输出**，断言 ① 必须变红——实测变异后 `min |tok| 求和 = 0.00`（未变异 **52.3**），
故这条断言对"它要抓的那个缺陷"是敏感的，**不是恒真守卫**（本计划的评审已被假守卫坑过三次）。

**② 30 步内组均值奖励有改善**（"在学"而非"跑通"）：前 10 步均值 **−28.69** → 后 10 步 **−14.46**
（奖励是三目标取负的加权和，**变大 = 改善**；30 步的逐步 r 见 `[A-e2e]` 打印）。

**③ 训练后 argmax 优于规则基线**：见 18.3。

### 18.3 ⭐ A 的关键数字（与规则基线对比）

| 量 | 数值 |
|---|---|
| **训练后 argmax makespan**（10 个扰动种子均值）| **86.8** |
| **规则基线 makespan**（每工序最短候选 + 规则派车，`seed_chain=0`）= `M_ref` | **103.4** |
| **训练后 / 规则** | **−16.1%** |
| **未训练对照**（同口径 argmax、同 10 种子、同初始权重）| **238.0 = 规则的 2.30×** |
| 训练 30 步的墙钟 | **244–278 s**（8.0–9.3 s/步，G=4，CPU；两次独占实测） |

- **未训练对照是"断言有牙齿"的判据**：不训练时同一条断言会以 **2.30×** 的差距变红——故
  "86.8 < 103.4"不是"随便初始化就好"的假通过。
- 参考运行本体的三目标：`f^ref = (103.42, 7.73, 19.51)` → `w = (0.051, 0.680, 0.269)`
  （权重由参考调度归一化得出，MK01 上 energy 的权重最大——因能耗绝对值最小）。
- ⚠️ **口径**：规则基线用的是 `rollout(seed_chain=0)`（**单**种子）；argmax 侧是 **10 种子均值**
  （brief 原设计）。两者不是同一个统计口径，**严格对照应同种子集重跑一遍规则**——已登记为开放
  线索（下 §18.5）。

### 18.4 长训练脚本 `plcsp/m13_train_a.py`

- CLI：`--inst/--steps/--G/--lr/--seed/--run-dir/--save-every/--eval-every/--eval-seeds/--resume`；
- **输出一律落 `run_dir`**（默认 `checkpoints/a_<inst>`，git-ignored）：`metrics.ndjson`（每步一行
  `{"step","r","t",…诊断}`；开 `--eval-every` 时另有 argmax 评估行）+ `ckpt.pt`。**不落包目录**；
- 已实测：2 步冒烟（metrics/ckpt/eval 三件都落盘）→ `--resume` 续跑成功（step 2 → 3）；
- 正式跑：`--inst mk01 --steps 300 --G 8 --eval-every 25`（后台）。**独占时实测 17.9–18.5 s/步**
  （与 Task 7 的 18.2 s 一致）；本次与全量回归**并行**跑，故 21 步用了 735 s（≈35 s/步，含争用）。
- **本次未跑完**（会话时长限制）：跑到 **step 20 / 300**，`ckpt.pt` 与 `metrics.ndjson` **同步停在
  20**（`--save-every 10`）⇒ 可**无损续跑**，不会出现 §18.4 上面说的重复 step。r 的走势
  （前 1/2 均值 **−18.5** → 后 1/2 均值 **−13.5**，上行、允许波动）已落盘可查。
- 续跑命令：`... -m plcsp.m13_train_a --inst mk01 --steps 300 --G 8 --eval-every 25 --resume`。

### 18.5 已知风险 / 开放线索（本节新增）

- 🔴 **P4 的算力账**（新）：验收实测 MK01 `G=8` ≈ 18 s/步 ⇒ 300 步/run ≈ 1.5 h；MK10 ≈ 7–8 h。
  P4 计划是 **5 组消融 × 3 实例 × 3–5 种子** ⇒ 45–75 run × (1.5–8 h) ≈ **3–25 天**（CPU-only）。
  **必须先定"每 run 多少步"与"实例-种子矩阵怎么砍"**，否则 P4 会被算力卡死（旧 spec §6.3 已算过
  一次同样的账，当时结论是"选项 A–D 待拍板"）。
- 🟠 **单实例**：A 的全部数字只在 MK01（10 作业 × 6 机）。**不许据此写跨实例结论**。
- 🟠 **规则基线的统计口径**：18.3 的规则数是**单种子**、argmax 是 **10 种子均值**。论文主表须
  **同种子集**重跑规则（便宜：规则 run ≈ 0.5 s）。
- 🟠 **跨进程不可复现**（Task 7 记录，已写进 `m13_train_a.py` docstring）：动作采样走**全局 torch
  RNG** ⇒ 只传 `seed=` 锁不住动作，同 seed 跨进程不逐位相同。**论文的种子对照必须在同一进程同一
  调用序列下做**；跨进程只保证统计可比（多 seed 均值）。**出路**：在训练**开始前**显式钉
  `torch.manual_seed(...)`——钉完（初始化 + 逐步采样）整条轨迹就确定了，跨进程可复现。验收测试
  正是这么做的（fixture 第一行 `torch.manual_seed(0)`，故 18.2/18.3 的数字可复现）；
  `m13_train_a.py` **故意不钉**（`--seed` 只表达仿真扰动流这一个语义）。
- 🟡 **单条序列的读数**（J=1、G=4，且只有 30 步）：18.2 的"奖励改善"是**一条训练轨迹**的观察，
  不是统计结论（没有多 seed 重复）；`r_std` / `A_std` / `grad_norm` 已在 metrics 里逐步留痕，
  供 P4 定 G 与步数。
- ⚪ **`epochs>1` 是空转**（Task 7 实测，链级 ratio 尺度所致）：默认路径 `epochs=1` 即纯组内
  REINFORCE，**不要**为了"更像 PPO"去开多 epoch。
