**先澄清"分批"实指**（此前文档只写"分批（batching）"，含义从未定死）：本项目实现的是**投放门控**，不是文献里的加工批。证据 `geosched/env/des.py:250`："`batch_cap` = **同时在途作业数上限**（分批门控：B 层决策的载体）"；`des.py:285`："先入 batch_cap 个，每完成一个作业补一个"。B 层动作 = `cap_opts=[None, 2, 1]`（`m3_smoke.py:25`）。
　→ 与文献中的 **lot-streaming（批量拆分流转）** 和 **parallel batch scheduling（同炉同时加工）** **均非同一决策**。

**依据（两条）**：

1. **文献侧：顶刊 PLCSP 基本无"批"**。§11.1 对位表 10 篇中仅 2 篇标"①分批 ✓"（IJPR 63(4) Lot-streaming、EJOR 326(2) parallel batch），且这 2 篇的"批"是**加工批**，与我们的投放门控不同——**用它们支撑"分批有文献基础"属偷换概念**。另：16 篇有明确贡献声明的论文，创新点归为 7 类（新问题变体 / 图表征 / 动作空间 / 多智能体架构 / 奖励设计 / 扰动触发 / 评测基准），**无一类是分批**。李新宇组对 PLCSP 的界定亦只有两件事："the essence of PLCSP is to provide a series of **operation-AGV pairs**"。
2. **实证侧：分批非杠杆且有害**。bug#8 修复前该环节是**死代码、从未被真测**（§二 bug#8a）；修复后诚实测量：cap=None 500–552 / cap=5 483–576 / **cap=2 656–747（显著变差）**；轴判据结论"**B（分批）门控非杠杆**"（§八）；π_B 自学得 `[0.47, 0.33, 0.21]`——**优先 cap=None，策略自己选择不门控**。

### 13.1 通道化多目标（variant A：`m6_opt_a`）❌ **已否决**

- **做法**：4 条奖励通道（makespan / tardy / moves / energy）**各自组内 z 化后等权求和**——与 MO-GRPO（arXiv 2509.22047）/ Multi-GRPO（2512.00743）的 reward-grouping 同构；设计意图 = 方差对齐、防奖励黑客、免手调权重（z 后各通道 N(0,1) → 等权即均匀贡献）。
- **结果**：30 种子 **mean = 386.93**（median 387.44，min 372.29）vs flat **371.05** → **更差（+4.3%）**；训练轨迹中 eval 平台 373–417 震荡，未见收敛到 flat 水平。
- **判定**：**无增益 → 否决**。与"组内相对已把奖励尺度消掉、无需再分通道"的既有结论一致；通道化引入的等权假设在这一域没有收益。
- **处置**：❌ 已否决，**内部存档**，不进论文（与树式分层、共演化同档）。

### 13.2 通道化 + GRPO-λ 时序折扣（variant B：`m6_opt_b`）❌ **已否决**

- **做法**：A 的通道化 + **GRPO-λ 时序折扣**（L 段 logp 按时效加权 w_t = λ^(T−1−t)，近期决策权重高；λ=0.9）——GRPO-λ（2510.00194）/ eligibility traces（2605.05965）同族。

- **判定**：**无增益 → 否决**。时序折扣未改变结论方向，且该口径仍建立在已被否决的通道化奖励上。
- **处置**：❌ 已否决，**内部存档**，不进论文。

### 18.5 已知风险 / 开放线索（本节新增）

- 🔴 **P4 的算力账**（新）：验收实测 MK01 `G=8` ≈ 18 s/步 ⇒ 300 步/run ≈ 1.5 h；MK10 ≈ 7–8 h。
  P4 计划是 **5 组消融 × 3 实例 × 3–5 种子** ⇒ 45–75 run × (1.5–8 h) ≈ **3–25 天**（CPU-only）。
  **必须先定"每 run 多少步"与"实例-种子矩阵怎么砍"**，否则 P4 会被算力卡死（旧 spec §6.3 已算过
  一次同样的账，当时结论是"选项 A–D 待拍板"）。
- 🟠 **单实例**：A 的全部数字只在 MK01（10 作业 × 6 机）。**不许据此写跨实例结论**。
- 🟠 **规则基线的统计口径**：18.3 的规则数是**单种子**、argmax 是 **10 种子均值**。论文主表须
  **同种子集**重跑规则（便宜：规则 run ≈ 0.5 s）。
- 🟠 **跨进程不可复现**（Task 7 记录，已写进 `m13_train_a.py` docstring）：动作采样走**全局 torch
  RNG** ⇒ 只传 `seed=` 锁不住动作，同 seed 跨进程不逐位相同。**论文的种子对照必须在同一进程同一
  调用序列下做**；跨进程只保证统计可比（多 seed 均值）。**出路**：在训练**开始前**显式钉
  `torch.manual_seed(...)`——钉完（初始化 + 逐步采样）整条轨迹就确定了，跨进程可复现。验收测试
  正是这么做的（fixture 第一行 `torch.manual_seed(0)`，故 18.2/18.3 的数字可复现）；
  `m13_train_a.py` **故意不钉**（`--seed` 只表达仿真扰动流这一个语义）。
- 🟡 **单条序列的读数**（J=1、G=4，且只有 30 步）：18.2 的"奖励改善"是**一条训练轨迹**的观察，
  不是统计结论（没有多 seed 重复）；`r_std` / `A_std` / `grad_norm` 已在 metrics 里逐步留痕，
  供 P4 定 G 与步数。
- ⚪ **`epochs>1` 是空转**（Task 7 实测，链级 ratio 尺度所致）：默认路径 `epochs=1` 即纯组内
  REINFORCE，**不要**为了"更像 PPO"去开多 epoch。

### 18.6 评审回修（2026-10-03，3 Important + 2 Minor）

### 19.7d ✅ MKT 口径核实结论（2026-10-03）

## 二十一、⑧ 交期口径重设计（TF/RDD）——死目标复活（2026-10-03）

**动机**：§20.4-2 实测「⑧ 对训练后策略是**死目标**」（五组 TWT 全 0.0）。本批把交期从
`d_j = τ·M_ref`（共同交期、锚在**自己的**参考调度上）换成**外生、逐作业、有跨度**的 TF/RDD 口径。
计划：`docs/superpowers/plans/2026-10-03-due-date-redesign.md`；spec 侧见 §3.5（已整节重写）。

### 21.1 根因：TWT ≡ 0 是**恒等式**，不是噪声、也不是超参没调好

共同交期（`d_j` 对所有作业同值）下：

```
TWT ≡ 0   ⟺   makespan ≤ τ·M_ref
```

实测：30 步训练后策略的 makespan **89.5**，而 `τ·M_ref = 0.90 × 103.4 = 93.1` ⟹ **没有任何作业会误期**
⟹ 五组消融的 TWT 全为 0.0。**三目标实际退化成两目标。**
第二个病是**内生**：`M_ref` 取自我们自己的参考调度，换车队规模就换交期（mk01：n_agv=1/3 →
109.95/103.42）——交期随求解配置漂，不是问题本身的属性。

### 21.2 新口径与冻结的 (τ, R) 表

```
W_j  = 作业 j 各工序最短候选工时之和（TWK）      LB = max(Σ_j W_j/m, max_j W_j)
ρ_j  = W_j 升序排名归一化到 [0,1]（n=1 取 0.5）  d_j = LB·τ·(1 + R·(2ρ_j − 1))
```

`LB` 只读实例数据 ⟹ **交期与车队规模/车速/通道宽全无关**（`test_due_dates_do_not_depend_on_fleet_size`）；
⑧ 只进目标读数 ⟹ makespan 在任何 (τ,R) 下**逐位相同**（测试钉 mk01；实施者对 10 实例 × 5 组 (τ,R) 实测全等，
同期 TWT 取 4–5 个互异值——证明覆盖开关真接上了，不是死开关）。
实现 `plcsp/env/due_dates.py`，标定脚本 `plcsp/m16_due_calib.py`；`SimConfig.tau` 从"唯一标定值"降级为
**覆盖开关**（新增 `due_range`）。

### 21.3 标定规则：为什么"改进后也不许退化"是硬约束

在 (τ,R) 网格上求满足「`0.20 ≤ 参考策略误期率 ≤ 0.75` **且** 改进 12%（`C_j × 0.88`）后同样落带」者中，
取 `|参考误期率 − 0.45| + |改进后误期率 − 0.40| + 0.02·R` 最小的一对。
**旧口径正是死在只对参考策略标定**：τ=0.90 对着未训练的策略选的，训练一改进（12–14%）就把 TWT 清零。
收紧 τ 是**保守方向**——只会让我们的 TWT 变大、不会把目标调没 ⟹ 本规则**不存在"调参美化结果"的激励**。

**R ∈ [0.2, 0.8] 的两条理由不同，不得混说**：下限 0.2 **不是可行性边界**（R=0 可行，只是退化成共同交期、
与"逐作业"的既定选择矛盾）；上限 0.8 是**硬约束**（`1+R(2ρ−1)` 在 R>1 时越过零点 ⟹ 负交期）。
